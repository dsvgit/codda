# Доменная документация

Как инженерные скиллы должны использовать доменную документацию этого репозитория при изучении кода.

## Перед изучением прочитать

- **`CONTEXT.md`** в корне репозитория, или
- **`CONTEXT-MAP.md`** в корне, если он есть: он указывает на отдельный `CONTEXT.md` для каждого контекста. Прочитать те, что относятся к теме.
- **`docs/adr/`**: прочитать ADR, затрагивающие область, в которой предстоит работать. В multi-context репозиториях также проверить `src/<context>/docs/adr/` — решения уровня контекста.

Если каких-то из этих файлов нет — **молча продолжать**. Не сообщать об их отсутствии и не предлагать создать их заранее. Скилл `/domain-modeling` (вызывается через `/grill-with-docs` и `/improve-codebase-architecture`) создаёт их лениво — когда термины или решения действительно определены.

## Структура файлов

Single-context репозиторий (большинство репозиториев, в том числе этот):

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

Multi-context репозиторий (признак — `CONTEXT-MAP.md` в корне):

```
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← решения уровня всей системы
└── src/
    ├── ordering/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← решения уровня контекста
    └── billing/
        ├── CONTEXT.md
        └── docs/adr/
```

## Использовать словарь глоссария

Когда в результате работы упоминается доменное понятие (в заголовке тикета, предложении по рефакторингу, гипотезе, названии теста), использовать термин так, как он определён в `CONTEXT.md`. Не переходить на синонимы, которые глоссарий явно помечает как нежелательные (_Avoid_).

Если нужного понятия в глоссарии ещё нет — это сигнал: либо вы изобретаете язык, которым проект не пользуется (стоит пересмотреть), либо это реальный пробел (отметить его для `/domain-modeling`).

## Сообщать о конфликтах с ADR

Если результат работы противоречит существующему ADR — явно сказать об этом, а не молча переопределять решение:

> _Противоречит ADR-0007 (event-sourced orders), но стоит пересмотреть, потому что…_
