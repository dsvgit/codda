# Процесс разработки с AI

Как устроена работа над codda: человек принимает решения и проверяет результат, Claude Code пишет спеки, код, тесты и отчёты. Процесс собран на скиллах Matt Pocock (плагин `mattpocock-skills`, v1.2.3) и сложился на Golden Path PoC. Что делать дальше — [HOW-TO-PROCEED.md](HOW-TO-PROCEED.md).

## Шпаргалка: что делать, когда…

| Хочу… | Делаю |
|---|---|
| Новую фичу | Ветка `git switch -c <feature>` → `/grill-with-docs <идея>` → `/to-spec` → `/to-tickets` (одна сессия) → по тикету: `/clear` + `/implement` |
| Вернуться после перерыва, не помню, где остановились | Спросить агента «где мы остановились?» — или по шагам из «[Как возобновить работу](#как-возобновить-работу)» |
| Сделать готовый тикет | `/clear` → `/mattpocock-skills:implement @.scratch/<feature>/issues/NN-<slug>.md` → прогнать сценарий руками |
| Мелкую правку | Прямо в сессии, без тикета → коммит (см. «Тикет или нет?») |
| Сделать что-то вне плана, но крупное | Описать агенту → «оформи тикет в `.scratch/<feature>/issues/`» → `/clear` + `/implement` |
| Понять, чего я вообще хочу | `/grill-with-docs` — агент задаёт вопросы; `/prototype` — черновик, который потом выбросим |
| Починить непонятный баг | `/diagnosing-bugs` |
| Узнать факты из документации библиотеки | `/research` |
| Спросить не по теме посреди тикета | Фоновый форк сессии, чтобы не засорять контекст |
| Зафиксировать решение из разговора | «Запиши это»: правило → `CLAUDE.md`, термин → `CONTEXT.md`, архитектура → ADR, на будущее → `docs/roadmap.md` |
| Не знаю, какой скилл нужен | `/ask-matt` |

## Тикет или нет?

Вопрос один: **нужно ли следующей сессии знать, что и зачем сделано?** Да — тикет. Хватит коммита — без тикета.

**Без тикета** — работа на одну сессию, после которой не остаётся решений и открытых вопросов:

- опечатка, документация, README, конфиг, переименование;
- очевидный баг в одном месте;
- вопрос: «как работает X?», «почему упал тест?».

Делаем прямо в сессии, без `/implement`. Два правила остаются:

1. Коммит с сообщением, из которого понятно **зачем**.
2. Решение, правило или находка из разговора — в файл (последняя строка шпаргалки).

**Сначала тикет**, если хотя бы одно верно:

- меняется поведение, которое проверяют тесты или видит студент;
- работа не влезает в одну сессию или её придётся продолжать;
- задача вне скоупа текущей стадии: тикет фиксирует, что скоуп расширен осознанно.

Тикету спека не обязательна: это короткий файл по шаблону из [docs/agents/issue-tracker.md](agents/issue-tracker.md). Агент оформит его по описанию. Тикеты, не относящиеся ни к одной фиче, — в `.scratch/misc/issues/`.

Пример: курс React Hooks в `courses/` по этому правилу требовал тикета — он меняет `App` и `main.tsx`, и теперь о нём приходится помнить в roadmap.

## Принципы

- **Всё знание — в репозитории.** Решение, термин, находка или правило, всплывшие в разговоре, сразу записываются в файл (таблица ниже). Следующая сессия начинается с `/clear` и знает только то, что лежит в git.
- **Тикет — единица работы и контекста.** Один тикет — одна свежая сессия. Тикет самодостаточен: из него, спеки, `CONTEXT.md` и ADR агент понимает задачу без истории чата.
- **Tracer bullets.** Тикет — вертикальный срез через все слои, который можно показать или проверить сам по себе. Первый тикет стадии — самый тонкий сквозной путь.
- **Стадия кончается решением.** Стадия (PoC, MVP) отвечает на вопросы своей спеки, итог — отчёт с решением go/no-go, обновлёнными ADR и roadmap.
- **Скоуп фиксирован в спеке.** Находка вне скоупа записывается (Comments тикета → roadmap), а не делается.

| Глоссарий: Lesson, Run, Sandbox, Test Report… | `CONTEXT.md` | `/domain-modeling` |

## Жизненный цикл

### 1. Идея → язык и решения

`/grill-with-docs <идея или файл>` — агент допрашивает человека по плану (`/grilling`) и по ходу записывает термины в `CONTEXT.md` и решения в ADR (`/domain-modeling`). Готово, когда у плана не осталось открытых вопросов, а каждый новый термин и решение есть в файлах.

Если сырьё уже есть (обсуждение в другом чате, заметки) — вставить его в сессию и попросить синтезировать глоссарий, ADR, спеку и тикеты. Так начинался PoC; grilling тогда пропустили, и его вопросы («главный шов — Runner?», «свой Test Harness?») решались уже в спеке.

Для большого туманного объёма (MVP) перед этим шагом — `/wayfinder`: карта решений `.scratch/<effort>/map.md` и тикеты-решения (`research` / `prototype` / `grilling` / `task`).

### 2. Спека

`/to-spec` в той же сессии — синтез разговора в `.scratch/<feature>/spec.md` без нового интервью: Problem Statement, Solution, User Stories, Implementation Decisions, Testing Decisions, Out of Scope. Агент сверяет с человеком **швы тестирования** — места, где тесты будут проверять поведение (в PoC: `run({ source, tests }) → TestReport` и e2e через UI).

### 3. Тикеты

`/to-tickets` в той же сессии — нарезка спеки на tracer-bullet тикеты с `Blocked by`. Человек утверждает нарезку: размер, связи, что слить или разбить. **Frontier** — тикеты, все блокеры которых `done`; независимые можно вести параллельно в отдельных git worktree.

Шаги 1–3 идут в одной сессии без `/compact`: спеке и тикетам нужен весь разговор.

### 4. Тикет

```
/clear
/mattpocock-skills:implement @.scratch/<feature>/issues/NN-<slug>.md
```

Что делает агент (`/implement`):

1. Читает тикет, спеку, `CONTEXT.md`, ADR. Ставит `Status: in-progress`.
2. Пишет код через `/tdd` на швах из спеки: тест → красный → код → зелёный. Объём тестов — по правилу стадии из `CLAUDE.md` → «Тесты».
3. Гоняет `npm run typecheck` и отдельные файлы тестов по ходу, полный `npm test` (и `npm run test:e2e`, если тикет его касается) — в конце.
4. `/code-review` — два параллельных сабагента: **Standards** (стандарты репо + базовый набор code smells) и **Spec** (соответствие тикету и спеке). Исправляет то, что нашли.
5. Отмечает выполненные критерии, ставит `Status: done` (или `ready-for-human`, если остался шаг только для человека). Дописывает в `## Comments`: что сделано, замеры, отклонения от спеки, находки для отчёта стадии, список «Не протестировано (на отдельный проход)».
6. Коммитит.

Что делает человек:

- Отвечает на вопросы агента и принимает решения по ходу. Решение, касающееся не только этого тикета, агент сразу записывает в файл: правило — в `CLAUDE.md`, задачу на будущее — в roadmap, решение по архитектуре — в ADR.
- Проходит сценарий руками (`npm run dev`).
- Побочный вопрос, не относящийся к тикету, задаёт в фоновом форке сессии, чтобы не засорять её контекст (так на тикете 03 обсуждали название «codda»).

### 5. Итог стадии

Последний тикет стадии — отчёт (`/implement` по тикету отчёта). Агент собирает ответы на вопросы спеки со ссылками на тесты-доказательства, перепроверяет замеры, сводит находки из `## Comments` всех тикетов в риски, обновляет ADR и roadmap. Человек принимает решение go/no-go и проводит демо.

## Как возобновить работу

Новый день, `/clear`, оборванная сессия — состояние процесса целиком лежит в git и `.scratch/`, вспоминать чат не нужно. Короткий путь: спросить агента «где мы остановились?» — он пройдёт шаги ниже и предложит следующую команду.

**1. Где мы.** `CLAUDE.md` → «Текущая стадия» и шаг в [HOW-TO-PROCEED.md](HOW-TO-PROCEED.md). Затем `git branch --show-current`, `git status`, `git log --oneline -5`: ветка подсказывает фичу (имя ветки = папка в `.scratch/`), незакоммиченные изменения — что работа оборвалась посреди тикета.

**2. Статусы тикетов фичи:**

```
grep -H 'Status:' .scratch/<feature>/issues/*.md
```

**3. Что делать — по первому подходящему статусу:**

| Нашёл | Делаю |
|---|---|
| `in-progress` | Тикет оборвался. `/clear` → `/mattpocock-skills:implement @<тикет>` с припиской «продолжи: смотри `## Comments` и `git diff`». Незакоммиченные изменения не откатывать |
| `ready-for-human` | Шаг за человеком — какой, написано в `## Comments` тикета (демо, решение). Сделать его и попросить агента закрыть тикет |
| `ready-for-agent`, все `Blocked by` в `done` | Это frontier: взять первый по номеру → `/clear` + `/implement` |
| Все тикеты `done` | Фича готова: следующая строка в HOW-TO-PROCEED (следующая фича, тикет-отчёт стадии) |

**Карта wayfinder** (`.scratch/<effort>/map.md`): `/clear` → `/wayfinder .scratch/<effort>/map.md` — скилл сам находит frontier. Тикет в `claimed` без `## Answer` — оборванный, продолжить его.

**Оборвались шаги 1–3** (grilling, спека, нарезка): им нужен весь разговор, поэтому сначала вернуть сессию — `claude --continue` (последняя) или `claude --resume` (выбор из списка). Если сессию не вернуть — `/grill-with-docs` заново, дав ему то, что уже записано: `CONTEXT.md`, новые ADR, черновик спеки.

| Разговор → спека | `/to-spec` | формат спеки PoC |
| Спека → тикеты | `/to-tickets` | формат тикетов 01–05 |
| Сделать тикет | `/implement` → `/tdd`, `/code-review` | все пять тикетов |
| Неясно, как должно выглядеть или вести себя | `/prototype` | — |
| Нужны факты из документации | `/research` | — |
| Сложный баг | `/diagnosing-bugs` | — (timeout в headless-shell отлаживали внутри `/implement`) |
| Ревью ветки или диффа | `/code-review` | внутри каждого `/implement` |
| Код начал расползаться | `/improve-codebase-architecture` | — |
| Правка `CLAUDE.md` или скилла | `/writing-for-agents` | этот документ |

Скиллы с `disable-model-invocation` (`/implement`, `/to-spec`, `/to-tickets`, `/grill-with-docs`, `/wayfinder`) запускает только человек. В Claude Code они называются с префиксом плагина: `/mattpocock-skills:implement`.

## Соглашения

- **Язык.** Документы — по-русски. Доменные термины — по-английски и с заглавной, как в `CONTEXT.md` (Lesson, Run, Test Report). Код, тесты, имена тестов — по-английски.
- **Ветки.** Одна фича — одна ветка от `main` (`git switch -c <feature-slug>`, имя как у папки в `.scratch/`); `/code-review` сравнивает с `main`. Тикеты, которые идут параллельно, — в отдельных git worktree. Мелкие правки без тикета — прямо в `main`. На PoC работали в `main`.
- **Коммиты.** Conventional-префикс (`feat:`, `test:`, `docs:`), заголовок о результате, тело — что и почему. Код — по-английски, документы — по-русски. Один тикет — обычно один `feat:`-коммит. Агент ставит `Co-Authored-By`.
- **`## Comments` тикета** — запись с датой и автором (`**2026-10-03 — реализация (агент).**`), затем пункты. Комментарии — сырьё для отчёта стадии: замеры с условиями, отклонения от спеки с причиной, риски с пометкой «для отчёта (NN)».
- **Отклонение от спеки** записывается в Comments, а не исправляется в спеке задним числом. Итоговые отклонения стадии — в разделе «Итог» спеки.

## Как прошёл PoC

Один день, девять сессий:

| Сессия | Что | Скиллы |
|---|---|---|
| 1 | Обсуждение архитектуры из другого чата → глоссарий, ADR 0001–0005, спека, тикеты 01–05, roadmap, `docs/agents/` | `/domain-modeling`, форматы `/to-spec`, `/to-tickets` |
| 2–6 | Тикеты 01–05, по сессии на тикет | `/implement` → `/tdd` → `/code-review` |
| 7 | Курс React Hooks в `courses/` (5 Lesson, `?lesson=<id>`) — вне тикетов | — |

Что сработало:

- **`/clear` + `/implement` по тикету.** Тикеты 02–05 сделаны без пересказа истории: контекст пришёл из файлов и `## Comments` предыдущих тикетов.
- **`/code-review` с осью Spec** ловил расхождения с тикетом до коммита.
- **Comments → отчёт.** Находки, записанные по ходу (timeout в `chrome-headless-shell`, утечка `fetch` из Sandbox, холодный Run), стали рисками R1–R10 отчёта без отдельного расследования.
- **Решения записывались сразу:** правило тестов PoC — в `CLAUDE.md` (тикет 01), «timeout вне Chrome» — в roadmap, блок A (тикет 02).

Отклонения от процесса — учесть на MVP:

- **Grilling пропущен:** спека синтезирована из готового обсуждения. На MVP — `/grill-with-docs` перед каждой спекой.
- **Тесты догоняли код в тикете 01:** правило «один happy-path тест на шаг» появилось после реализации, тест написан отдельным коммитом. С тикета 02 — red → green.
- **Статусы:** тикет 01 остался `in-progress` с пустыми чекбоксами (исправлено при наведении порядка). Агент закрывает тикет сам, на шаге 5.
- **Работа без тикета:** курс React Hooks (`courses/`) сделан одним запросом. Он не нужен для Golden Path, его формат Lesson временный и уступит Lesson Manifest (блок C). Отсюда правило «Тикет или нет?».
- **Тикет 05 ждал демо в `ready-for-human`,** хотя PoC уже везде был назван завершённым. Закрыт после демо.
