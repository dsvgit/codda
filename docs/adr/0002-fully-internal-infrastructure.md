# Полностью внутренняя инфраструктура, браузер без доступа в Internet

Браузер студента в production не обращается ни к одному внешнему хосту: ни к CodeSandbox, ни к CDN (unpkg, jsDelivr, esm.sh), ни к npmjs.org. Всё — бандл приложения, `esbuild.wasm`, Dependency Artifacts — отдаётся с нашего origin. Это корпоративное требование безопасности и предсказуемости, и оно должно проверяться автоматически (e2e с заблокированной внешней сетью), а не только на ревью.

Уточнение (тикет `.scratch/mvp/issues/06-ci-and-pilot-hosting.md`): требование делится на два. **Правило для браузера** — всё с одного нашего origin, сторонних хостов нет, проверяется автоматически — свойство самого `codda`; оно действует в любой установке. **Закрытый контур** — внутренние npm registry, раннеры CI, образы и хостинг — свойство конкретной установки. `codda` его поддерживает (registry из `.npmrc`, Chromium через внутреннее зеркало Playwright, GitLab-шаблон CI с внутренним образом и выкладкой в S3), но не требует. Пилот этого репозитория идёт на github.com: GitHub Actions ставят пакеты из npmjs.org, сборка выкладывается на публичные GitHub Pages, а браузер по-прежнему ходит только на origin Pages.

## Consequences

- В закрытом контуре npm-зависимости ставятся только в CI из внутреннего npm registry (ADR-0005, ADR-0006).
- Любая библиотека, которая в рантайме лезет в сеть (шрифты, телеметрия, lazy-chunks с CDN), недопустима без патча.
