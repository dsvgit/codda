# Инструмент `codda` отделён от контента курсов

`codda` — это инструмент: CLI, Runtime и UI. Курс — это контент, папка с файлами, путь к которой инструмент получает параметром (`codda dev <путь>`, `codda build <путь>`). Кроме этой папки инструмент о курсах ничего не знает. `codda build` выдаёт папку статических файлов, которую можно отдать с любого нашего веб-сервера. В MVP backend нет. Так авторы смогут вести курсы в своих репозиториях, а у инструмента одна точка входа для контента.

В MVP курсы лежат в этом же репозитории (`courses/`), потому что для одного пилотного курса отдельный репозиторий и публикация пакета `codda` — лишняя работа. Граница при этом проходит в коде и проверяется в CI: начиная с фичи `lesson-manifest`, код инструмента не импортирует ничего из `courses/`. Сейчас, после PoC, такие импорты есть.

## Consequences

- npm registry для Dependency Artifacts берётся из стандартной конфигурации npm (`.npmrc` курса или пользователя), а если её нет — из registry по умолчанию. В закрытом контуре `.npmrc` указывает на внутренний registry. Это уточнение ADR-0005: CLI не задаёт registry сам. ADR-0002 не нарушается, потому что в сеть ходит сборка, а не браузер.
- Вынести курсы в отдельный репозиторий можно без переделок инструмента. Для этого нужно только опубликовать `codda` как пакет.
- Прогресс и Workspace в MVP хранятся только в браузере, потому что сборка статическая.
