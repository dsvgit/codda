## Раунд 1

### Q1 — Что проверять у Starter в `codda test`

Ошибка типов в Starter — предупреждение (Q9 тикета 05). Но проверять Starter можно по-разному, и от этого зависит, сколько `⚠` увидит Author.

- **(a) Starter один, как в редакторе студента.** В окружении только файл Starter, lib и `types.json`. Предупреждение значит ровно «студент откроет Lesson и сразу увидит подчёркивание».
- **(b) Starter вместе с Lesson Tests.** Ловит ещё и несовпадение сигнатур, но почти каждый Starter даёт `⚠`: тесты импортируют из `./main` то, чего в заготовке ещё нет или что пока имеет другой тип. Студент таких ошибок не видит: Lesson Tests в его Type Checker не входят.

➡️ **Рекомендация:** (a). Предупреждение должно означать то, что увидит студент. Несовпадение тестов с Solution и так ловит строгая проверка Solution + Lesson Tests.

## Предложения в общие документы

- **`CONTEXT.md`, термин Type Checker:** дописать, что тот же код проверки типов работает в `codda test` (в Node) и что в браузере Type Checker видит только файл Workspace, без Lesson Tests.
- **ADR-0009, Consequences:** две строки. (1) lib-файлы берутся из `typescript-6` по списку из модуля конфига: в UI — один JSON с content-hash, в `codda test` — прямо из пакета. (2) Lesson Tests проверяются в `codda test` с объявлением `@codda/test`, которое несёт инструмент; `tsc -b` сверяет его с Test Harness.
- **ADR-0009, Consequences, третья строка:** Compiler выбирает loader esbuild по расширению файла (`.ts` / `.tsx`), это часть общего конфига TS.
- **`docs/roadmap.md`:** правок нет. Всё отложенное (hover, auto-import, signature help, строка «Есть ошибки типов» в Test Report) уже в «MVP, часть 2».
