## Раунд 1

### Q1 — Порядок Lesson и раскладка Module

Возможны два варианта.

- **(a) Явный список в `course.yaml`:** `modules: [{ title, lessons: [use-state, use-effect, …] }]`. Папки Lesson без числового префикса, их имена стабильны. Порядок меняется одной строкой в YAML, и ничего не переименовывается.
- **(b) По префиксу папки:** `01-use-state/` и т.д. Список не нужно поддерживать, но при переупорядочивании меняются имена папок. Module тогда тоже папка (`01-basics/01-use-state/`).

Вариант (a) решает и то, где живёт Module: в MVP Module существует только в `course.yaml`, отдельной папки у него нет, папки Lesson лежат прямо в корне Course. Если Lesson есть на диске, но не указан в `course.yaml` (или наоборот), это ошибка `codda test`.

➡️ **Рекомендация:** (a). От ответа зависит идентичность Lesson (раунд 2).

**Ответ:**
a

### Q2 — Раскладка файлов Lesson и имя файла Workspace

По T5 файлы плоские: `starter.tsx`, `solution.tsx`, `lesson.test.tsx`. Но тесты импортируют `./App`, а студент видит какое-то имя файла во вкладке редактора. Варианты:

- **(a) Плоско + фиксированное имя:** студент видит `starter.tsx` как `App.tsx`, тесты всегда импортируют `./App`. Просто, но в «MVP, часть 2» (multi-file) формат придётся ломать.
- **(b) Папки:** `starter/App.tsx`, `solution/App.tsx`, `lesson.test.tsx`. Имя файла Workspace — это имя файла в `starter/`. Multi-file потом ляжет без смены формата. В MVP правило: в `starter/` ровно один файл, в `solution/` — те же имена.

➡️ **Рекомендация:** (b). На один уровень вложенности больше сейчас, зато миграция в части 2 не понадобится. Имя файла берётся из Starter, а не захардкожено.

**Ответ:**
давай переименуем starter в main и оставим такие же импорты в тестах - main, но не будем делать вложенные папки, оставим структуру плоской

### Q3 — Формат зависимостей

Map как в `package.json`, только с точными версиями:

```yaml
# course.yaml
dependencies:
  react: 19.3.0
  react-dom: 19.3.0
```

```yaml
# lesson.md frontmatter
dependencies:
  zustand: 5.0.8
```

- Версия — строгий semver `X.Y.Z` (допускается prerelease). Диапазоны (`^`, `~`, `*`, `latest`) дают ошибку `codda test`.
- Набор Lesson = Course ∪ Lesson. Если Lesson объявляет пакет, который уже есть в Course, с другой версией, это ошибка (рекомендация research).
- Subpath (`react-dom/client`) отдельно не объявляется: точки входа `codda` выводит из импортов Starter/Solution/Lesson Tests. `@codda/test` — встроенный модуль Runtime, а не зависимость.
- `@types/*` — открытый вопрос тикета 08. Схема оставляет место: если их нужно объявлять явно, они пишутся в тот же map.

➡️ **Рекомендация:** так, как выше. Повтор в Lesson пакета из Course даже с той же версией — тоже ошибка: дубли маскируют будущие расхождения при обновлении Course.

### Q4 — Валидация: JSON Schema или код

- **(a) Zod-схема в коде:** TS-типы выводятся из схемы, есть кросс-файловые проверки (Lesson из `course.yaml` существует на диске, конфликт версий) в том же месте. JSON Schema для автодополнения в редакторе можно потом сгенерировать (`z.toJSONSchema`).
- **(b) Рукописная JSON Schema + ajv:** стандарт, но кросс-файловые правила всё равно придётся писать кодом, и правила окажутся в двух местах.

➡️ **Рекомендация:** (a), Zod. Генерацию JSON Schema для редактора в MVP не делаем.

### Q6 — Поля frontmatter и `course.yaml`, откуда берётся заголовок

Минимальный набор:

- `course.yaml`: `title` (обяз.), `dependencies` (необяз., по умолчанию `{}`), `modules` (обяз., ≥1). У Module обязательны `title` и `lessons` (≥1).
- `lesson.md` frontmatter: `title` (обяз.), `dependencies` (необяз.). Тело файла — Instructions, Markdown без обязательного H1, потому что заголовок UI рисует из `title`.

Ничего сверх этого (description, сложность, теги, hints) в MVP не добавляем, как требует ограничение скоупа в `CLAUDE.md`.

➡️ **Рекомендация:** ровно этот набор. Заголовок только во frontmatter. Если тело начинается с `# …`, это не ошибка, и предупреждать об этом не нужно.

### Q8 — Идентичность Lesson

Прогресс и сохранённый Workspace (7.2, 7.3) хранятся в браузере по ключу. После Q1 у Lesson есть стабильное имя — имя его папки.

- id Lesson = имя папки. Формат — kebab-case: `^[a-z0-9]+(-[a-z0-9]+)*$`. id уникален внутри Course: это гарантирует файловая система, а повтор в `course.yaml` — ошибка.
- Перенос Lesson между Module или смена порядка ключ не меняет.
- Переименование папки = новый Lesson: прогресс и Workspace студента по старому id теряются. Принимаем, `codda` это не отслеживает.
- id нужен и в URL: `/#/<lesson-id>` или `?lesson=<id>` (детали — в прототипе экрана, тикет 04).

### Q10 — Сохранённый Workspace после того, как Author поменял Starter

Студент начал Lesson, а потом вышла новая сборка курса, в которой `main.tsx` (или тесты) другие. Варианты:

- **(a) Оставить код студента как есть.** Новый Starter студент получит через Reset. Ничего не хранится и не сравнивается.

### Q11 — Как `codda test` сообщает об ошибках манифеста

Формат вывода и коды выхода CLI в целом решаются в тикете 05. Здесь решаем только ошибки манифеста:

- Проверка не останавливается на первой ошибке: собираются все ошибки по всему Course, затем вывод и ненулевой код выхода.
- Одна ошибка — одна строка: путь к файлу относительно корня Course, путь к полю, сообщение. Например:
  `use-state/lesson.md: dependencies.react: версия "^19.3.0" не точная, нужна X.Y.Z`
  `course.yaml: modules[0].lessons[2]: папки "use-memo" нет`
- Если манифест невалиден, сборка и тесты этого Lesson не запускаются, а остальные Lesson проверяются.
- Язык сообщений — русский, как весь UI.

## Раунд 3

### Q13 — Что допустимо в Markdown Instructions

Instructions рендерятся в странице приложения, а не в Sandbox. Поэтому важно, что Markdown может в них вставить.

- **Raw HTML** (`<div>`, `<script>`, `<img onerror=…>`). Author сейчас доверенный, но при показе в parent любой HTML исполняется с правами приложения. Это задача security baseline (блок F), и проще закрыть её сразу: raw HTML не рендерится, а выводится как текст.
- **Картинки и ссылки на файлы рядом с `lesson.md`** (`![](diagram.png)`). Их пришлось бы копировать в сборку и проверять в `codda test`. Пяти Lesson React Hooks они не нужны.
- **Внешние ссылки** (`[MDN](https://…)`) — это обычные ссылки, студент переходит сам. ADR-0002 не нарушается: браузер ничего не грузит без клика. Но в закрытом контуре они могут не открываться.

➡️ **Рекомендация:** CommonMark + GFM (таблицы, код с подсветкой — подсветку решает прототип экрана, тикет 04). Raw HTML выключен. Картинки в MVP не поддерживаются: `codda test` выдаёт ошибку, если в Instructions есть `![…](…)`. Внешние ссылки разрешены.
