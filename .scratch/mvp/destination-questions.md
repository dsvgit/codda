## Q2 — Что лежит в конце карты

Карта решает вопросы и ничего не строит. В конце может быть одно из трёх:

- **(a)** набор спек фич из таблицы «Рекомендуемый порядок фич» (от `lesson-manifest` до `pilot-course`). Все вопросы, нужные для `/to-spec` по каждой фиче, решены. Реализация идёт вне карты.
- **(b)** решения и ADR только по развилкам с неизвестными: B-зависимости, A-loop-guard, E-TS в Worker, F-origin/CSP, C-Manifest. Тогда каждую фичу можно спокойно грилить по `/grill-with-docs`. Спеки не входят.
- **(c)** весь путь до работающего MVP, с исполнением внутри карты. Противоречит правилу «Plan, don't do».

➡️ **Рекомендация:** **(b)**. В конце карты нет ни одного открытого архитектурного вопроса, который мешает начать `/grill-with-docs` → `/to-spec` по любой фиче из таблицы. В частности, нужны ADR по loop-guard (R3), по способу доставки Dependency Artifacts (R4/R5/R9), по Sandbox origin + CSP (R2) и решённая схема Lesson Manifest. Сами спеки пишутся по фичам, иначе карта превратится во вторую копию процесса `/to-spec`.
