## T4 — Зависимости на уровне Lesson (ваши комментарии к 1.1 и 5.5)

Да, это хорошее решение. Строка 5.1 ровно это и означает: Lesson Manifest перечисляет нужные пакеты, CI их собирает, и браузер получает только их. Мой вариант:

- Список зависимостей задаётся **на уровне Course** (например, `react`, `react-dom` для всех Lesson). Lesson может **добавить** свои пакеты. Иначе одни и те же пакеты придётся повторять в каждом из 5–10 Lesson.

## T5 — В чём хранить описание Lesson: JSON или frontmatter (ваш вопрос к 1.1)

Раз в MVP Lesson — это один файл решения, предлагаю такую структуру:

```
courses/react-hooks/
  course.yaml          # название, порядок Module/Lesson, зависимости Course
  01-use-state/
    lesson.md          # frontmatter (title, зависимости Lesson) + текст Instructions
    starter.tsx
    solution.tsx
    lesson.test.tsx
```

- **Frontmatter в `lesson.md`**: у Lesson меньше файлов, а метаданные лежат рядом с текстом. Автору удобно, и редакторы подсвечивают Markdown.
- **Отдельный `manifest.json`**: машине проще читать и валидировать по JSON Schema. Но автор правит два файла вместо одного.

Lesson Manifest — это понятие из `CONTEXT.md`, а не обязательно отдельный файл. При frontmatter Lesson Manifest = frontmatter + файлы по соглашению об именах.

➡️ **Рекомендация:** frontmatter в `lesson.md` + `course.yaml`. Окончательную схему (поля, валидация, порядок Lesson) решить отдельным тикетом-grilling «Схема Lesson Manifest».

## T8 — Последствия того, что отложено (3.1, 3.2, 8.x)

Вы отложили security и часть runtime-hardening. Это нормально, но у каждого решения есть цена, и её лучше назвать заранее.

**T8.1 — Security.** В пилоте студент запускает только свой код в своём браузере. Чужой код к нему не попадает, потому что всё хранится локально. Поэтому без security baseline риск в пилоте низкий. Когда появится сервер или обмен кодом (7.4), риск перестаёт быть низким: код студента может ходить во внутреннюю сеть (R2).

➡️ **Рекомендация:** записать правило «security baseline (8.1–8.4) обязателен до 7.4 и до любых внешних пользователей».
