# 03: Асинхронные ошибки во время тестов (R8)

**What to build:** исключение в таймере или незахваченный reject, случившиеся во время теста, валят этот тест, а остальные тесты выполняются и попадают в Test Report. Сейчас такая ошибка превращает весь Run в `runtime-error` и теряет результаты, а незахваченный reject не виден вовсе (R8 [PoC Report](../../../docs/poc-report.md)). Test Harness слушает `error` и `unhandledrejection` весь Run и приписывает ошибку текущему тесту; окно теста — до конца его промиса плюс один macrotask. Исключение на верхнем уровне модулей по-прежнему `runtime-error`. Правила — в спеке, раздел «Асинхронные ошибки».

**Blocked by:** `lesson-manifest` (Compiler отдаёт Workspace как `./main`); внутри фичи — None

**Status:** ready-for-agent

- [ ] Тест, внутри которого код студента бросает в `setTimeout(…, 0)`, получает `fail` с сообщением этой ошибки; следующие тесты выполнены и прошли — тест на шве Runner
- [ ] Незахваченный `Promise.reject(new Error("x"))` в коде студента во время теста → этот тест `fail` с `x` — тест
- [ ] Reject не-`Error` (`Promise.reject("oops")`) → `fail` с `oops` — тест
- [ ] Async-тест, у которого после `await` бросает таймер с задержкой, пока тест ещё ждёт → падает именно он, а не соседний — тест
- [ ] Тест, уже упавший на `expect`, сохраняет первую ошибку, даже если потом пришла асинхронная — тест
- [ ] Ошибка в таймере, сработавшем после последнего теста (задержка 1 с), не меняет отчёт: все тесты на месте — тест
- [ ] `throw` на верхнем уровне модуля студента → по-прежнему `runtime-error` (существующий тест зелёный)
- [ ] `npm run typecheck`, `npm test`, `npm run test:e2e` зелёные
