# 05: Восстановление после падения Worker Compiler'а

**What to build:** если Worker Compiler'а не смог загрузить `esbuild.wasm`, упал при `initialize` или не загрузил свой скрипт, Run сразу заканчивается отчётом `internal-error`, а не ложным timeout «ищите бесконечный цикл». Worker уничтожается, следующий Run поднимает новый и снова грузит `.wasm` — сейчас после неудачного `initialize` Worker сломан до перезагрузки страницы. Автоматического повтора нет. Во вкладке «Тесты» — красное «Внутренняя ошибка», сообщение и «Запустите тесты ещё раз». Текст timeout перечисляет реальные причины: бесконечный цикл, зависший промис, нехватка памяти (так покрывается и падение процесса Sandbox). См. спеку, раздел «Падение Worker Compiler'а».
