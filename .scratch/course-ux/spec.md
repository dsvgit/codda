## Problem Statement

К этой фиче у студента уже есть экран Lesson: Instructions, редактор, тулбар (`▶ Запустить тесты` ⇄ `■ Отмена`, `↺ Сбросить`, `Показать решение`), нижняя панель с вкладками «Тесты», «Console», «Проблемы», «Решение». Course загружается из `course.json`, Lesson выбирается фрагментом `#/<lesson id>`, по умолчанию открывается первый.

Пройти по этому экрану Course из 5–10 Lesson неудобно:

- Перейти к следующему Lesson можно, только вписав его id в адресную строку. Студент не видит, какие Lesson есть в Course и где он сейчас.
- Студент не знает, какие Lesson он уже прошёл и сколько осталось.
- Перезагрузка страницы, случайно закрытая вкладка или переход на другой Lesson стирают код студента. Вернуться к недоделанному Lesson — значит начать со Starter заново.

## Solution

Экран Lesson становится экраном Course (вариант «IDE» из прототипа тикета 04):

```
┌──────────────────┬──────────────────────┬──────────────────────────────────────────┐
│ « React Hooks    │ useEffect            │ ▶ Запустить тесты ↺ Сбросить Показать    │
│ Пройдено 1 из 5  │                      │ решение      ‖ ← Предыдущий  Следующий → │
│ ██░░░░░░░░       │ Instructions …       ├──────────────────────────────────────────┤
│ ▾ Хуки           │                      │ main.tsx (редактор)                      │
│   ✓ useState     │                      │                                          │
│   ▸ useEffect    │                      ├──────────────────────────────────────────┤
│     useRef       │                      │ Тесты 3/3 · Console · Проблемы · Решение │
│     useReducer   │                      │ ✓ PASS · 3 / 3   [Следующий урок →]      │
│     useContext   │                      │                                          │
└──────────────────┴──────────────────────┴──────────────────────────────────────────┘
```

- **Дерево Course** слева: название Course, «Пройдено N из M» с полоской, Module и их Lesson по порядку из `course.yaml`. Текущий Lesson выделен, у пройденных стоит ✓, клик открывает Lesson. Кнопкой `«` дерево сворачивается в узкую полосу, чтобы отдать ширину редактору, и разворачивается обратно.
- **Навигация:** `← Предыдущий` / `Следующий →` в тулбаре идут по Lesson в порядке Course, через границы Module. При PASS в баннере Test Report есть кнопка «Следующий урок →».
- **Адрес** Lesson — фрагмент `#/<lesson id>`. Каждый переход меняет фрагмент, поэтому кнопки браузера «Назад» и «Вперёд», ссылка и перезагрузка открывают тот же Lesson.
- **Прогресс:** Lesson пройден, когда Run дал PASS по всем тестам. Отметка остаётся навсегда: Reset, сломанный код и следующий FAIL её не снимают.
- **Workspace** каждого Lesson сохраняется в браузере при каждой правке и возвращается после перехода на другой Lesson, перезагрузки и закрытия вкладки.
- Прогресс и Workspace живут в `localStorage`, ключи содержат `id` Course. Если хранилище недоступно или переполнено, всё работает как раньше, только в памяти, и студент видит одну строку предупреждения.

## User Stories

1. Как студент, я хочу видеть слева список всех Lesson Course, сгруппированных по Module, чтобы понимать, из чего состоит Course.
2. Как студент, я хочу видеть Lesson в том же порядке, что задал Author в `course.yaml`, чтобы идти по Course так, как он задуман.
3. Как студент, я хочу видеть, на каком Lesson я сейчас, по выделению в дереве, чтобы не терять место.
4. Как студент, я хочу открыть любой Lesson кликом в дереве, чтобы вернуться к пропущенному или повторить пройденный.
5. Как студент, я хочу свернуть дерево Course, чтобы редактору и Instructions досталось больше ширины.
6. Как студент, я хочу развернуть свёрнутое дерево одной кнопкой, чтобы снова увидеть список.
7. Как студент, я хочу видеть ✓ у пройденных Lesson, чтобы знать, что уже сделано.
8. Как студент, я хочу видеть «Пройдено N из M» и полоску прогресса, чтобы знать, сколько осталось до конца Course.
9. Как студент, я хочу, чтобы Lesson отмечался пройденным, как только Run дал PASS по всем тестам, без отдельной кнопки «Сдать».
10. Как студент, я хочу, чтобы отметка «пройден» оставалась после Reset, чтобы спокойно экспериментировать с пройденным Lesson.
11. Как студент, я хочу, чтобы отметка «пройден» оставалась, даже если я потом сломал код и получил FAIL, чтобы эксперименты не стирали прогресс.
12. Как студент, я хочу, чтобы Run, который завершился ошибкой компиляции, runtime-ошибкой или timeout, не отмечал Lesson пройденным.
13. Как студент, я хочу перейти к следующему Lesson кнопкой `Следующий →`, чтобы не искать его в дереве.
14. Как студент, я хочу вернуться к предыдущему Lesson кнопкой `← Предыдущий`.
15. Как студент, я хочу, чтобы с последнего Lesson одного Module `Следующий →` вёл на первый Lesson следующего Module, чтобы Module не мешали идти подряд.
16. Как студент, я хочу видеть `← Предыдущий` неактивной на первом Lesson и `Следующий →` неактивной на последнем, чтобы понимать, что дальше идти некуда.
17. Как студент, я хочу после PASS нажать «Следующий урок →» прямо в баннере, чтобы сразу перейти дальше.
18. Как студент, я хочу на последнем Lesson Course видеть в баннере PASS вместо кнопки сообщение, что это последний урок, чтобы понимать, что Course закончен.
19. Как студент, я хочу, чтобы адрес страницы указывал на открытый Lesson, чтобы отправить ссылку на него или добавить в закладки.
20. Как студент, я хочу, чтобы кнопки браузера «Назад» и «Вперёд» переключали Lesson, которые я открывал, как на обычном сайте.
21. Как студент, я хочу после перезагрузки страницы оказаться на том же Lesson.
22. Как студент, я хочу, открыв адрес Course без Lesson, попасть на первый непройденный Lesson, чтобы продолжить с того места, где остановился.
23. Как студент, я хочу, открыв ссылку на несуществующий Lesson (например, Author его переименовал), попасть на понятное место Course, а не на сломанную страницу.
24. Как студент, я хочу, чтобы мой код сохранялся сам при каждой правке, без кнопки «Сохранить».
25. Как студент, я хочу после перезагрузки страницы увидеть свой код, а не Starter.
26. Как студент, я хочу, уйдя на другой Lesson и вернувшись, увидеть свой код в том виде, в каком его оставил.
27. Как студент, я хочу после закрытия браузера и возвращения на следующий день найти свой код и прогресс на месте.
28. Как студент, я хочу, чтобы Reset возвращал Starter и это тоже сохранялось, чтобы после перезагрузки не вернулся старый код.
29. Как студент, я хочу откатить Reset через `Ctrl/Cmd+Z`, и чтобы откат тоже сохранился.
30. Как студент, я хочу, чтобы при переходе на другой Lesson Test Report, Console и «Проблемы» показывали новый Lesson, а не результаты предыдущего.
31. Как студент, я хочу, чтобы `Ctrl/Cmd+Z` в новом Lesson не возвращал код предыдущего Lesson.
32. Как студент, я хочу, чтобы переход на другой Lesson во время Run отменял этот Run, чтобы результат старого Lesson не попал в новый.
33. Как студент, я хочу, чтобы PASS по одному Lesson никогда не отметил пройденным другой Lesson.
34. Как студент, я хочу, чтобы Type Checker после перехода подчёркивал ошибки в коде нового Lesson с типами его Lesson Tests.
35. Как студент, я хочу, чтобы при недоступном хранилище браузера (приватный режим с запретом, политика браузера) экран всё равно работал, а меня предупредили, что прогресс и код не сохранятся.
36. Как студент, я хочу, чтобы при переполненном хранилище работа не ломалась, а я узнал, что код перестал сохраняться.
37. Как студент, я хочу, чтобы испорченная запись в хранилище (кто-то правил её руками) не ломала экран: Lesson открывается со Starter.
38. Как студент, я хочу, чтобы два Course на одном адресе пилота не путали мой прогресс и код между собой.
39. Как студент, я хочу, чтобы в двух открытых вкладках прогресс не терялся: Lesson, пройденный в одной вкладке, остаётся пройденным.
40. Как студент, я хочу, чтобы Lesson, который я ещё не трогал, открывался с актуальным Starter, даже если Author его поменял.
41. Как Author, я хочу, чтобы перестановка Lesson и перенос между Module не сбрасывали прогресс и код студентов.
42. Как Author, я хочу, чтобы Lesson, удалённый из Course, просто пропадал из дерева и из «N из M», не ломая экран.
43. Как разработчик, я хочу e2e-тест «правка → перезагрузка → код на месте» и «PASS → перезагрузка → ✓ на месте» на собранной раскладке, чтобы сохранение проверялось так же, как на хостинге.
44. Как разработчик, я хочу, чтобы все e2e этой фичи шли с заблокированной внешней сетью, как остальные (ADR-0002).

## Implementation Decisions

- **Порядок Lesson** — плоский список «все Lesson всех Module по порядку `course.yaml`», выводится из уже загруженного Course. Он один на всё: `← Предыдущий` / `Следующий →`, «Следующий урок →», «первый непройденный», M в «N из M». Отдельной модели навигации нет.
- **Текущий Lesson определяется только фрагментом.** Экран слушает `hashchange` и открывает Lesson из `#/<lesson id>`. Все переходы (тулбар, дерево, баннер) только меняют фрагмент, поэтому каждый добавляет запись в историю браузера, и «Назад» работает без отдельного кода. Перезагрузки страницы при переходе нет: `course.json`, Runtime и Type Checker остаются живыми.
- **Фрагмент без Lesson** (`#`, `#/`, пусто) открывает первый непройденный Lesson; если пройдены все — первый (Q1). **Неизвестный id** во фрагменте — тот же выбор. В обоих случаях фрагмент заменяется на настоящий id без новой записи в истории (`replaceState`), чтобы «Назад» не возвращал на пустой адрес. Это меняет поведение по умолчанию из `lesson-manifest` («первый Lesson»).
- **Переход на другой Lesson** — это смена Lesson целиком: идущий Run отменяется тем же механизмом, что `■ Отмена` из `runtime-hardening` (Q3); Test Report, Console, «Проблемы» и «Решение» очищаются или показывают новый Lesson; редактор получает новое состояние с Workspace нового Lesson и пустой историей отмены; Type Checker получает новый файл студента и Lesson Tests нового Lesson. Отметку «пройден» ставит Run только своему Lesson: Lesson, для которого запущен Run, запоминается при старте, а не берётся из текущего на момент ответа.
- **PASS** — Test Report вида «тесты», где тестов ≥ 1 и все прошли. Ошибка компиляции, runtime-ошибка, timeout, отменённый Run и пустой список тестов — не PASS. Ошибки типов на PASS не влияют (ADR-0009).
- **Баннер PASS** (зелёный, из тикета 04) получает кнопку «Следующий урок →». На последнем Lesson Course кнопки нет, вместо неё текст «Это последний урок курса». Если `lesson-manifest` или `runtime-hardening` баннер ещё не сделали, его делает эта фича.
- **Дерево Course** — новая колонка слева от Instructions: название Course, «Пройдено N из M» и полоска (`<progress>` или эквивалент с `role="progressbar"`), Module заголовками, Lesson — ссылками `#/<lesson id>` с `title` из frontmatter. Текущий Lesson помечен `aria-current="page"`, пройденный — ✓ и доступным текстом «пройден». Module не сворачиваются: в MVP Module один. Сворачивается всё дерево целиком; свёрнутое состояние не сохраняется (живёт до перезагрузки).
- **Хранилище — один маленький модуль** поверх `localStorage` с тремя операциями: прочитать Workspace Lesson, записать Workspace Lesson, прочитать / поставить отметку «пройден». Все ключи с префиксом `codda:` (на GitHub Pages origin `dsvgit.github.io` общий для всех репозиториев владельца) и содержат `<course id>/<lesson id>`:
  - `codda:<course id>/<lesson id>:workspace` — текст Workspace как есть;
  - `codda:<course id>/<lesson id>:passed` — значение `"1"`.

  Ключ на каждый Lesson, а не один объект прогресса на Course: запись отметки не читает и не переписывает чужие, поэтому две вкладки не затирают прогресс друг друга. Перестановка Lesson и перенос между Module ключ не меняют (тикет 03). Значения — строки без JSON, поэтому «испорченная запись» — это только чужое значение у `:passed`; отметкой считается ровно `"1"`, остальное — «не пройден».
- **Когда пишется Workspace:** синхронно на каждое изменение документа в редакторе, без debounce (один файл в несколько КБ). Workspace, совпадающий со Starter, не хранится: ключ удаляется. Так Reset очищает запись, а Lesson, который студент не менял или вернул к Starter, после правки Starter Author'ом открывается с новым Starter. Изменённый Workspace после правки Starter остаётся как есть (тикет 03); плашки «Starter обновлён» нет.
- **Чтение Workspace** при открытии Lesson: сохранённый текст, если он есть, иначе Starter.
- **Недоступное или полное хранилище** (Q2). Любое обращение к `localStorage`, включая сам доступ к свойству, обёрнуто в `try/catch`. Ошибка чтения = записи нет. Ошибка записи не прерывает правку и Run: Workspace и отметки живут в памяти страницы до перезагрузки. При первой ошибке хранилища над редактором один раз появляется строка «Код и прогресс не сохраняются: хранилище браузера недоступно или переполнено» и остаётся до перезагрузки. Повторных попыток, очистки старых ключей и квот нет.
- **Синхронизации вкладок нет.** Событие `storage` не слушаем: вторая вкладка увидит чужой прогресс и код после перехода или перезагрузки. Workspace одного Lesson в двух вкладках — «последняя запись выигрывает».
- Курс, Lesson и порядок берутся только из `course.json`; код UI курсы не импортирует (ADR-0008). Новых npm-зависимостей нет.

## Testing Decisions

- **Хороший тест** проверяет то, что видит студент: какой Lesson открыт (заголовок, фрагмент), что в редакторе, какие ✓ в дереве, что написано в «Пройдено N из M» и баннере. Не проверяем вызовы React, внутреннее состояние экрана и точный формат ключей там, где можно проверить поведение через перезагрузку.
- **Шов 1 — e2e Playwright** на собранной раскладке (та же, что выкладывается на Pages и что открывает `codda test`), с фикстурой блокировки внешней сети (`e2e/offline`). Главный шов фичи: перезагрузка, история браузера, настоящий `localStorage`. Сценарии: Golden Path через навигацию (`Следующий →` → правка → Run → PASS → «Следующий урок →»), перезагрузка сохраняет Lesson, Workspace и ✓, «Назад»/«Вперёд», адрес без Lesson и с неизвестным id.
- **Шов 2 — компонентный тест экрана Lesson** в Vitest browser mode с Course-фикстурой — тот шов, что ввела фича `lesson-manifest` (prior art — тест `App` из PoC). Здесь граничные случаи, которые неудобно ставить в e2e: `localStorage`, бросающий на чтении и записи (`Storage.prototype` подменяется в тесте), испорченное значение `:passed`, Lesson из хранилища, которого нет в Course, переход во время Run, ошибки компиляции / timeout не дают ✓, первый и последний Lesson (неактивные кнопки, текст в баннере), переход через границу Module (фикстура из двух Module).
- **Модуль хранилища** отдельных unit-тестов не получает: он проверяется через экран, где видно его поведение. Отдельный тест — только если иначе не поставить граничный случай.
- **Runner** не меняется, его тесты не трогаем.
- Prior art: `src/App.test.tsx` (Vitest browser, рендер экрана, `page.getByRole`), `e2e/golden-path.e2e.ts` и `e2e/offline.ts` (Playwright, проекты `dev` и `pages`). Новых швов фича не вводит.
- Тесты по правилу MVP: ошибки и граничные случаи — в тикете, где появляется поведение, не отдельным проходом.

## Out of Scope

- Прогресс и Workspace на сервере, вход пользователя, синхронизация между устройствами (7.4, «MVP, часть 2»).
- Подсказки и счётчик попыток (7.5).
- Плашка «Starter обновлён — Reset, чтобы взять новый» и хранение hash Starter (кандидат roadmap, если всплывёт в пилоте).
- Синхронизация открытых вкладок через событие `storage`.
- Сворачивание отдельных Module, сохранение свёрнутого состояния дерева, поиск по Lesson.
- Сброс прогресса студентом, экспорт/импорт прогресса.
- Обработка переименованного Lesson: новый id — новый Lesson, старые ключи остаются мусором в хранилище (тикет 03).
- Multi-file Workspace.

## Further Notes

- Адрес пилота не меняется до конца пилота: прогресс в `localStorage` привязан к origin (тикет 06).
- Ключи `<course id>/<lesson id>` закреплены тикетом 03: переименование папки Lesson = новый Lesson.
- Если к началу фичи баннер PASS, отмена Run или смена Lesson в Type Checker устроены не так, как предполагает эта спека, отличие записывается в `## Comments` тикета, спека не переписывается.
