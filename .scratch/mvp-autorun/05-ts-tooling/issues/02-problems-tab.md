# 02: Вкладка «Проблемы», статус Type Checker и смена Lesson

**What to build:** в нижней панели экрана Lesson появляется вкладка «Проблемы» (договорённость 4 в `README.md`). На вкладке счётчик ошибок, внутри список `строка:колонка — сообщение (TSxxxx)`; клик по строке ставит курсор в редактор. Пока Type Checker грузится, на вкладке «…» и текст «Проверка типов загружается». Если он не загрузился или упал — «Проверка типов недоступна», подчёркивания убираются, а редактор и Run работают. Type Checker стартует после первой отрисовки экрана, он один на сессию. При переходе к другому Lesson (`#/<lesson id>`) меняется только файл: lib JSON и `types.json` повторно не грузятся. Подробности — «Клиент Type Checker» и «Вкладка «Проблемы»» в [spec.md](../spec.md).

## Comments

- Статус Type Checker — хранилище модуля в `src/type-checker/client.ts` (`typeCheckerStatus`, `onTypeCheckerStatus`), экран читает его через `useSyncExternalStore`. До старта воркера статус `loading`: он стартует сразу, первым запуском linter'ов в эффекте монтирования редактора Workspace (`forceLinting`), то есть после первой отрисовки.
- Воркер шлёт `ready`, когда lib-файлы и `types.json` загружены и окружение построено. Запросы ждут `ready` на стороне клиента, а воркер отвечает на них синхронно. Поэтому исключение TypeScript посреди сессии становится событием `error` у Worker, и клиент уходит в `unavailable` по той же ветке, что и при незагруженном скрипте. Ошибка построения окружения — `failed`.
- Список вкладки «Проблемы» берётся из того же ответа, что и подчёркивания: обвязка linter'а отдаёт ошибки через `onTypeErrors`, только если текст не изменился за время проверки. Пока первой проверки нет, на вкладке «…» и «Проверка типов загружается».
- В `unavailable` подчёркивания убираются так: смена статуса — пустая транзакция с `userEvent` `codda.relint` плюс `forceLinting`. Одного `forceLinting` мало: `@codemirror/lint` запускает его, только если перепроверка уже запрошена. Прежний `codda.compile-errors` переименован в `codda.relint`, теперь им пользуются оба случая.
- Клик по строке — `EditorHandle.goTo(from)`: курсор и `focus()`. Строка списка — `<button>` в `<ul aria-label="Проблемы">`.
- Смена расширения Starter: ядро помнит текущий файл студента, другое имя удаляет старый файл (`env.deleteFile`) — заметка из Comments тикета 01. Unit-тест в `core.test.ts` (скрипты с одним `const` дали бы TS2451) и e2e на курсе-фикстуре через `page.route` `course.json` (`main.tsx` → `main.ts` → `main.tsx`): в React Hooks все Starter — `main.tsx`.
- e2e — `e2e/problems.e2e.ts`. Падение посреди сессии имитируется `worker.evaluate` с `throw` в `setTimeout`. Тест «one Type Checker per session» из 01 заменён более полным тестом здесь: он считает ещё запросы lib JSON и `types.json`.
- Компонентный тест `App.test.tsx` по-прежнему идёт без Type Checker. В нём вкладка «Проблемы» без счётчика (`unavailable`), поэтому ожидаемый список вкладок дополнен.
