# 01: Переход между Lesson — адрес `#/…`, `← Предыдущий` / `Следующий →`, «Следующий урок →»

**What to build:** Студент ходит по Lesson Course, не трогая адресную строку. В тулбаре справа от `Показать решение` появляются `← Предыдущий` и `Следующий →`, они идут по всем Lesson всех Module в порядке `course.yaml`. В зелёном баннере PASS — кнопка «Следующий урок →», на последнем Lesson вместо неё текст «Это последний урок курса». Адрес открытого Lesson — фрагмент `#/<lesson id>`: каждый переход меняет фрагмент, экран слушает `hashchange` и меняет Lesson без перезагрузки страницы, поэтому «Назад»/«Вперёд» браузера, ссылка и перезагрузка открывают нужный Lesson. Пустой фрагмент и неизвестный id открывают первый Lesson Course и заменяют фрагмент на его id без новой записи в истории (тикет 04 этой фичи меняет это на «первый непройденный»). Переход — смена Lesson целиком: идущий Run отменяется, нижняя панель показывает новый Lesson, у редактора пустая история отмены, Type Checker проверяет новый Lesson. Workspace в этом тикете при уходе с Lesson теряется (сохранение — тикет 02). См. [спеку](../spec.md), раздел Implementation Decisions.

**Blocked by:** фичи `lesson-manifest`, `runtime-hardening`, `ts-tooling` целиком (порядок [autorun](../../README.md)).

## Comments

- Фрагмент теперь читает сам экран: `App({ course })` берёт Lesson из `#/<id>` через `useSyncExternalStore` по `hashchange`; `Root` в `main.tsx` больше не держит id. Служебная страница `codda test` (`#/__codda-test`) решается один раз при загрузке страницы: экран Lesson на ней не рисуется вовсе. Компонентный тест ставит фрагмент `history.replaceState` перед рендером, как это делает страница.
- Все переходы (тулбар, баннер) — присваивание `location.hash`, то есть новая запись в истории и `hashchange`. Пустой фрагмент, `#/`, неизвестный id и битое `%`-экранирование (`decodeURIComponent` бросает) открывают первый Lesson, фрагмент заменяется `history.replaceState` в эффекте. Экран «Урок „<id>“ не найден» удалён вместе с компонентным тестом и e2e `course.e2e.ts`.
- Смена Lesson по-прежнему — новый экземпляр `Lesson` (`key={lesson.id}`): чистые Test Report, Console, вкладка, новый редактор с пустой историей отмены, Type Checker получает новый файл (механизм ts-tooling/02, его e2e в `problems.e2e.ts` идут через `#/…` и не менялись). Отмена Run при уходе — `cancel.current?.abort()` в cleanup эффекта `Lesson`, тот же `AbortController`, что у «■ Отмена». Видно по тому, что Sandbox (`iframe[sandbox]`) пропадает за <1 с, а не через 5 с; без cleanup тест красный.
- Баннер PASS стал `<div class="banner">`: текст и справа «Следующий урок →» или «Это последний урок курса». Тест цвета баннера смотрит на `.banner`, а не на текст. Кнопки `← Предыдущий` / `Следующий →` прижаты к правому краю тулбара (`.spacer`).
- Компонентный тест перехода во время Run использует Run, который ждёт (`test` с вечным промисом), а не бесконечный цикл: с ещё одним busy-loop Sandbox в `App.test.tsx` `runner.test.ts` под нагрузкой полного `npm test` падал на таймингах (2 прогона из 4, с повторами `CI=true`). Без busy loop — зелёный 3 раза подряд. См. «Отложенные проблемы».
- e2e — новый `e2e/navigation.e2e.ts`, идёт в проектах `dev` и `pages` (в `playwright.config.ts` у `dev` теперь два файла). На `npm run dev` `course.json` грузится дважды при старте (StrictMode запускает эффект дважды), поэтому тест считает загрузки только после первого Lesson.
- Не сделано (не в критериях): баннер «Все тесты пройдены» по-прежнему показывается и для Test Report с 0 тестов — PASS для прогресса определит тикет 04.
- Проверки: `npm run typecheck` зелёный; `npm test` с `CI=true` — 234 passed, 1 skipped (17 файлов); `npm run test:e2e` — 50 passed.
