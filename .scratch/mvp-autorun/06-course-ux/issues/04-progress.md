# 04: Прогресс — ✓ у пройденных Lesson и «Пройдено N из M»

**What to build:** Lesson становится пройденным, когда Run дал PASS: Test Report вида «тесты», тестов ≥ 1, все прошли. Отметка пишется в `localStorage` ключом `codda:<course id>/<lesson id>:passed` со значением `"1"` и больше не снимается: Reset, сломанный код, FAIL, ошибка компиляции не трогают её. В дереве Course у пройденных Lesson ✓ (с доступным текстом «пройден»), над списком «Пройдено N из M» и полоска с `role="progressbar"`; M — Lesson в текущем `course.json`, N — пройденные из них, ключи удалённых Lesson не считаются. Адрес без Lesson и неизвестный id теперь открывают первый непройденный Lesson, а если пройдены все — первый. Хранилище — модуль из тикета 02, его ошибки обрабатываются так же: отметка живёт в памяти, видна та же строка предупреждения. См. [спеку](../spec.md).

## Comments

- Хранилище — тот же `storage.ts`: `passed(lessonId)` (ключ `codda:<course id>/<lesson id>:passed` равен ровно `"1"` или отметка поставлена на этой странице) и `markPassed(lessonId)` (пишет только свой ключ, `setItem(key, "1")`, без чтения чужих). Отметки, поставленные на странице, всегда держатся ещё и в `Set` в памяти: снять их нельзя, поэтому память не мешает второй вкладке, а при ошибке записи ✓ остаётся до перезагрузки. Ошибка записи — тот же `fail()` и та же строка предупреждения; ошибка чтения — «не пройден», `failed` без подписчиков (чтение в рендере), как у Workspace.
- Подписка хранилища обобщена: `onFailure` → `subscribe` (зовётся при первой ошибке и при каждой новой отметке) и снимок `version()`. `App` читает отметки всех Lesson Course на каждом рендере и перерисовывается по `useSyncExternalStore(storage.subscribe, storage.version)`, поэтому ✓ и «N из M» меняются сразу после PASS. `Lesson` остался на `storage.failed` — новая отметка его не перерисовывает.
- PASS — `isPass(report)`: вид `tests`, тестов ≥ 1, все прошли. Отметку ставит `onRun` экземпляра `Lesson` (`key={lesson.id}`) своему `lesson.id`: Lesson фиксирован на весь Run, уход с Lesson отменяет Run (`cancelled`, не PASS). Ошибки типов в PASS не участвуют по построению (Run их не видит, ADR-0009); отдельного теста нет — в `App.test.tsx` Type Checker отключён.
- Заметка из тикета 01 закрыта: Test Report с 0 тестов — «FAIL · 0 / 0», красный счётчик `0/0`, без баннера «Все тесты пройдены» (как `codda test`: «в Lesson Tests нет ни одного теста» — ошибка).
- Дерево: под заголовком «Пройдено N из M» и `<progress value max aria-label="Прогресс курса">` (неявная роль `progressbar`); M — все Lesson `course.json`, включая `BrokenLesson` `codda dev`. ✓ — `<span role="img" aria-label="пройден">` после названия в DOM (имя ссылки «<title> пройден»: в Vitest `getByRole` имя точное, ссылка с ✓ впереди «пройденСложение» не находилась бы по названию), визуально — абсолютом слева, в отступе ссылки. Ширина дерева и тулбар не менялись (тест 1280×800 зелёный).
- Пустой фрагмент и неизвестный id — первый непройденный Lesson, все пройдены — первый; `replaceState` из тикета 01 без изменений.
- Тесты: компонентные в `App.test.tsx` (10 новых, все красные до кода): PASS → ✓, «1 из 2», `value` полоски, Reset + FAIL + «перезагрузка» держат ✓; ошибка компиляции, runtime, FAIL, отмена, 0 тестов; timeout (Run с вечным промисом, без busy loop, ~5 с); переход во время Run, который прошёл бы через 1,5 с; испорченное `"true"`; запись только своего ключа (шпион `setItem`, чужие ключи целы); ключ удалённого Lesson и другого Course не считается; первый непройденный / все пройдены; `setItem` бросает — ✓ до перезагрузки, одно предупреждение; `getItem` бросает — 0, PASS ставит ✓ в памяти. e2e — новый `e2e/progress.e2e.ts` в проектах `dev` и `pages`; красным отдельно не прогонялся (без кода экрана не собирается сборка).
- Проверки: `npm run typecheck` зелёный; `npm test` — 253 passed, 1 skipped (17 файлов) с `CI=true` (без него падал известный флейк `cli/test-command.test.ts` «a foreign request…», см. «Отложенные проблемы»); `npm run test:e2e` — 62 passed.
