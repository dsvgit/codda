# 03: Асинхронные ошибки во время тестов (R8)

**What to build:** исключение в таймере или незахваченный reject, случившиеся во время теста, валят этот тест, а остальные тесты выполняются и попадают в Test Report. Сейчас такая ошибка превращает весь Run в `runtime-error` и теряет результаты, а незахваченный reject не виден вовсе (R8 [PoC Report](../../../../docs/poc-report.md)). Test Harness слушает `error` и `unhandledrejection` весь Run и приписывает ошибку текущему тесту; окно теста — до конца его промиса плюс один macrotask. Исключение на верхнем уровне модулей по-прежнему `runtime-error`. Правила — в спеке, раздел «Асинхронные ошибки».

**Blocked by:** `lesson-manifest` (Compiler отдаёт Workspace как `./main`); внутри фичи — None

## Comments

- **Test Harness** (`runtime/harness.ts`): слушает `error` и `unhandledrejection` весь Run. До `runAll` `error` — по-прежнему `runtime-error` (верхний уровень модулей). После старта `runAll` ошибка идёт текущему тесту: `failCurrentTest` пишет `message` (`Error`) или `String(x)` и сохраняет первую ошибку (`??=`), так что упавший на `expect` тест не перезаписывается. Тест считается законченным, когда закончился его промис; между тестами и после последнего ошибки не видны (после отчёта Sandbox уничтожается). Runner и форма Test Report не менялись.
- **Окно теста — конец промиса плюс два macrotask, а не один** (отступление от буквы спеки при той же сути). Находка: Chrome сообщает о незахваченном reject отдельной задачей, которая встаёт после первого `setTimeout(0)` харнесса, и при одном macrotask reject синхронного теста доставался следующему тесту (красный тест «unhandled rejection with an Error»). Двух хватает стабильно (3 прогона подряд).
- **Поменялись два существующих теста** (поведение по R8, не регрессия): «lines printed after the report do not reach onConsole» — таймер `console.log("late")` с задержкой 100 мс вместо 0 (нулевой теперь попадает в окно теста и печатается до отчёта); e2e «student code's fetch to the Internet does not get through» — `fetch(…).catch(() => {})`: оборванный offline-фикстурой `fetch` теперь незахваченный reject и валит первый тест (было `2 / 3`, стало бы `1 / 3`), а тест про изоляцию, не про R8.
- **TDD.** Red → green: таймер с нулевой задержкой (было `runtime-error`), `Promise.reject(new Error("x"))` (был `pass`, после первого кода — ошибка у соседнего теста, отсюда два macrotask). **Зелёные сразу** (поведение дал первый срез), способность упасть проверена мутациями: reject не-`Error` (мутация `JSON.stringify` вместо `String` → красный), таймер с задержкой в async-тесте (окно с конца промиса → красный), первая ошибка сохраняется (`=` вместо `??=` → красный). «Ошибка в таймере через 1 с после последнего теста» зелёная по построению — отчёт уже ушёл до таймера; это страховка от регрессии, мутации, которая его роняет, нет. «`throw` на верхнем уровне» — существующий тест, зелёный.
- **Вне критериев:** reject на верхнем уровне модуля (`Promise.reject` при импорте) приходит уже после старта `runAll` и валит первый тест, а не даёт `runtime-error` — Chrome сообщает о нём задачей позже; в спеке «До `runAll`» сформулировано для `error`, отдельно не тестировалось. Таймер, запущенный в одном тесте и сработавший в следующем, валит следующий (минус варианта (a) Q1, принят).
- `npm run typecheck`, `npm test` (95 passed, 2 skipped — флейк из runtime-hardening/02), `npm run test:e2e` (13) зелёные локально.
