# 02: Console студента во вкладке «Console»

**What to build:** `console.log/info/warn/error/debug` из Sandbox — код студента, Lesson Tests, предупреждения React — видны во вкладке «Console» нижней панели (между «Тесты» и «Решение»), по мере появления. На вкладке счётчик строк. Console очищается на старте каждого Run; строки, выведенные до timeout или отмены, остаются. Test Harness перехватывает console и шлёт каждую строку сообщением `codda:console`; Runner проверяет форму (ADR-0003) и отдаёт строки через `onConsole`. Лимиты — 1000 строк за Run и 10 000 символов на строку, с обеих сторон. Форматирование и лимиты — в спеке, раздел «Console в Sandbox».

**Blocked by:** `lesson-manifest` (нижняя панель экрана Lesson)

## Comments

- **Runner** (`runtime/runner.ts`): `run(input, { timeoutMs?, signal?, onConsole? })`. `isConsoleFor` проверяет `runId`, `level` (один из пяти) и `text` (строка). Лимиты Runner держит сам: 1000 строк и 10 000 символов на строку; на 1001-й строке отдаёт warn «Console: показаны первые 1000 строк, остальное отброшено», дальше молчит. Новые типы `ConsoleLine`, `ConsoleMessage` — в `types.ts`.
- **Канал — `MessagePort`, а не `window.postMessage`.** Находка: Chrome доставляет `window.postMessage` от iframe только после конца отправляющей задачи. Поэтому `console.log("start"); while (true) {}` не отдавал `start` до timeout (проверено пробой: порт доставляет сразу). Sandbox в bootstrap-скрипте `srcdoc` создаёт `MessageChannel` и передаёт порт сообщением `codda:port` (Runner проверяет `event.source` и `runId`). Бандл лежит в `<script type="text/plain">` и запускается следующей задачей, а `codda:report` и `codda:console` идут через порт. При `dispose` порт закрывается, поэтому поздние строки не доходят. Принято человеком; ADR-0003 и спека (п. «Протокол postMessage») поправлены.
- **Test Harness** подменяет `console.log/info/warn/error/debug` до кода студента. Строки выводятся как есть, `Error` — через `String(err)`, остальное — через `format()` сообщений `expect`. Лимиты — те же константы, продублированные: harness компилируется из исходника в бандл и не может их импортировать.
- **Экран Lesson:** вкладка «Console» между «Тесты» и «Решение», счётчик — серый бейдж (только при строках > 0). Строки — текстом в `<li>` с классом уровня: warn — тёмно-жёлтый на светло-жёлтом, error — красный. Пустая Console показывает «Нет вывода». Очищается на старте Run, «Тесты» открывается и в начале, и после конца Run.
- **TDD.** Red → green: форматирование и level, timeout со строкой `start` (стал красным из-за находки про `postMessage`), 1000 строк в harness, лимит Runner при обходе harness, обрезка в harness, обрезка в Runner, форма и чужой `runId`, оба UI-теста экрана. **Зелёные сразу:** порядок строк вместе с Lesson Tests (путь первого среза); «после отчёта не доходят» (что тест может упасть, проверено мутацией: без `port.close()` он красный); «перекрывающиеся Run» (у каждого Run свой порт, по построению).
- **Флейк (правило 7, «Отложенные проблемы» в README).** Первый Run после Sandbox с бесконечным циклом иногда не стартует. Воспроизводится на чистом `657a07c`, к этому тикету не относится. `test.skip` со ссылкой: «after a cancelled Run … gives PASS», «Run from «Решение» opens «Тесты»…» в `App.test.tsx`. Новый UI-тест очистки Console стоит раньше теста с отменой, чтобы не наследовать флейк; гонка в нём (прошлый PASS виден, пока идёт Run) снята ожиданием `▶ Запустить тесты`.
- **Вне критериев:** Sandbox может создать сколько угодно портов и прислать `codda:port` второй раз — Runner берёт только первый (слушатель снимается). Строки console не привязаны к тесту (out of scope спеки).
