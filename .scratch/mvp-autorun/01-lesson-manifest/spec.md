## Problem Statement

После PoC курс — это TypeScript-модули со строками внутри (`courses/react-hooks/*.ts`), а UI импортирует их напрямую и выбирает Lesson параметром `?lesson=`. Отсюда три проблемы.

- **Author** не может писать Lesson как обычные файлы: Instructions, Starter, Solution и Lesson Tests сидят в строковых литералах одного `.ts`, без подсветки и проверки типов. Ошибки в описании курса никто не ловит, пока студент не нажмёт Run.
- **Граница ADR-0006 нарушена:** код инструмента импортирует `courses/`. Курс нельзя передать путём, а сборка UI меняется вместе с контентом.
- **Студент** видит прототипный экран PoC: английские надписи, Instructions простым текстом, нет Reset и показа Solution. По умолчанию открывается PoC-задание Counter, которого нет ни в одном Course.

## Solution

Course — папка с `course.yaml` и папками Lesson (`lesson.md`, `main.ts(x)`, `solution.*`, `lesson.test.*`), формат из тикета 03. Модуль чтения Course проверяет его Zod-схемой и сообщает **все** ошибки сразу, одной строкой на ошибку: `<файл от корня Course>: <путь>: <сообщение>`, по-русски.

Минимальный `codda build <путь> [--out]` копирует заранее собранный UI, кладёт рядом `course.json` и PoC-артефакт зависимостей `deps/` (договорённости 1 и 2 в `README.md`). UI при старте загружает `course.json` через `fetch` с `cache: "no-cache"` и открывает Lesson из фрагмента `#/<lesson id>`, по умолчанию первый.

Экран Lesson — по прототипу тикета 04, без дерева Course и навигации (их добавит `course-ux`):

```
┌──────────────────────────────────────────────────────────────────┐
│ React Hooks · useState                                           │
├────────────────────────┬─────────────────────────────────────────┤
│ Instructions           │ ▶ Запустить тесты · ↺ Сбросить ·        │
│ (Markdown → HTML)      │ Показать решение                        │
│                        ├─────────────────────────────────────────┤
│                        │ main.tsx (редактор Workspace)           │
│                        │                                         │
│                        ├─────────────────────────────────────────┤
│                        │ [Тесты 2/3] [Решение]                   │
│                        │ ✓ is closed at first                    │
│                        │ ✗ opens on click — expected …           │
│                        │ FAIL · 2 / 3                            │
└────────────────────────┴─────────────────────────────────────────┘
```

Левая колонка (дерево Course) появится в `course-ux`, вкладки «Console» и «Проблемы» — в `runtime-hardening` и `ts-tooling` (договорённость 4).

Пять Lesson React Hooks переведены на новый формат. PoC-формат удалён: `courses/index.ts`, `courses/react-hooks/*.ts`, `courses/courses.test.ts`, PoC-задание Counter и параметр `?lesson=`. CI проверяет, что код инструмента не импортирует `courses/`, а пилот выкладывается из выхода `codda build`.

## Implementation Decisions

### Формат Course на диске

Ровно как в `## Answer` тикета 03, без зависимостей (их ведёт `package.json` Course, ADR-0007, это фича `dependency-artifacts`):

- `course.yaml`: `id` (kebab-case `^[a-z0-9]+(-[a-z0-9]+)*$`), `title`, `modules` (≥1), у Module — `title` и `lessons` (≥1, id Lesson). Неизвестные поля — ошибка.
- Lesson — папка в корне Course, имя папки = id Lesson. `lesson.md`: frontmatter между `---` с единственным полем `title`, тело — Instructions. `main.ts` или `main.tsx` — ровно один. `solution.<расширение main>`. `lesson.test.ts` или `lesson.test.tsx` — ровно один. Лишние файлы не проверяем.
- Кросс-файловые правила: Lesson из списка есть на диске; папка с `lesson.md` в корне Course есть в списке; id не повторяется ни внутри Module, ни между Module.

### Модуль чтения Course (Node)

Глубокий модуль с одной функцией: путь к Course → либо данные `course.json`, либо список строк ошибок. Внутри: чтение `course.yaml` и frontmatter пакетом `yaml`, Zod-схемы (strict, TS-типы выводятся из них), кросс-файловые правила, проверка Instructions (с тикета 04). Сообщения Zod — по-русски (встроенная локаль `ru` или свои сообщения, на выбор реализации). Путь к полю — как в тикете 03: `modules[0].lessons[2]`. Синтаксическая ошибка YAML — `<файл>: строка N: <сообщение>`. Ошибки собираются по всему Course: ошибка в одном Lesson не останавливает проверку остальных. Если есть хоть одна ошибка, результат — только список строк. Разбивку по Lesson для `codda test` добавит `author-cli`, когда она понадобится.

Модуль используют `codda build` и dev-сервер инструмента (Q1). Позже его же возьмут `codda test` и `codda dev` (`author-cli`).

### `course.json` — граница ADR-0006 и ADR-0008

Тип живёт в коде инструмента, его читают и модуль чтения, и UI. UI `course.json` Zod-ом не проверяет: файл пишет наш же `codda build`.

```ts
type CourseData = {
  id: string;
  title: string;
  modules: { title: string; lessons: LessonData[] }[];
};
type LessonData = {
  id: string;
  title: string;
  instructions: string;             // HTML, готовый в codda build (Q2); до тикета 04 — исходный Markdown
  workspace: { name: "main.ts" | "main.tsx"; starter: string };
  solution: string;
  tests: string;                    // Lesson Tests, импортируют "./main"
};
```

Ни версии формата, ни зависимостей, ни путей к файлам в нём нет: сборка UI и `course.json` всегда выкладываются вместе.

### Минимальный `codda build`

`codda build <путь> [--out <папка>]`, по умолчанию `--out` = `<путь>/dist`.

1. Нет `course.yaml` по пути, неизвестный флаг, нет собранного UI → одна строка, код `2`. Собранный UI — результат `npm run build` инструмента (по ADR-0008 — `dist-tool/`). Строка подсказывает выполнить `npm run build`.
2. Ошибки Course → все строки в stderr, код `1`, папка `--out` не создаётся и не меняется.
3. Иначе копирует UI в `--out`, пишет `course.json` и копирует PoC-артефакт в `deps/` (как его сейчас ждёт Compiler), код `0`.

Не делает (это `author-cli`): поиск `course.yaml` вверх без пути, пересборку устаревшего UI, маркер `.codda-build` и очистку `--out`, Dependency Artifact из `package.json`.

### UI

- **Загрузка:** точка входа UI загружает `course.json` относительно страницы (`fetch(..., { cache: "no-cache" })`), затем рисует экран. Ошибка сети или не-2xx → «Не удалось загрузить курс» и кнопка «Обновить». Пока грузится — «Загрузка курса…».
- **Выбор Lesson:** фрагмент `#/<lesson id>`, без фрагмента — первый Lesson первого Module. Неизвестный id → «Урок „<id>“ не найден» и ссылка на первый Lesson. Смена фрагмента (`hashchange`) открывает другой Lesson с чистого листа: Starter в редакторе, без Test Report, вкладка «Тесты». `document.title` = `<Lesson> — <Course>`.
- **Компонент экрана Lesson** получает `CourseData` и id Lesson пропсами. Это шов для браузерных unit-тестов: курс в тесте — литерал, без `fetch`.
- **Тулбар** над редактором: `▶ Запустить тесты` · `↺ Сбросить` · `Показать решение`. Во время Run кнопка запуска недоступна и показывает «Выполняется…» (`■ Отмена` — `runtime-hardening`). Место справа под `← Предыдущий` / `Следующий →` оставлено пустым (`course-ux`).
- **Нижняя панель**, вкладки `Тесты` · `Решение`. После каждого Run активна «Тесты». Счётчик на «Тесты»: `N/M` зелёным при PASS, красным при FAIL, красный `✗` при ошибке компиляции, runtime-ошибке и timeout; до первого Run — без счётчика и с подсказкой «Нажмите „Запустить тесты“».
- **Test Report** на русском. Тесты: `✓ <имя>` / `✗ <имя> — <ошибка>`, итог `PASS · M / M` или `FAIL · N / M`. При PASS сверху зелёный баннер «Все тесты пройдены» (кнопку «Следующий урок →» в баннер добавит `course-ux`). Ошибка компиляции — красный заголовок «Ошибка компиляции» и строки `Строка N:M — <сообщение>`; runtime-ошибка — «Ошибка выполнения» и stack; timeout — «Превышено время: 5 с» и подсказка про бесконечный цикл. Имена тестов и тексты ошибок приходят от Lesson Tests и esbuild как есть.
- **Решение:** `Показать решение` открывает вкладку «Решение»: CodeMirror только для чтения с Solution. Workspace не меняется, отдельной кнопки «Скрыть» нет.
- **Reset:** одна транзакция редактора, заменяющая весь документ на Starter. История отмены сохраняется, `Ctrl/Cmd+Z` возвращает код студента. Отметок о прохождении нет (это `course-ux`), Test Report после Reset остаётся.
- **Instructions:** HTML из `course.json` вставляется в центральную колонку. Markdown превращается в HTML пакетом `marked` (CommonMark + GFM) внутри `codda build` (Q2). Raw HTML (блочный и строчный) экранируется и выводится как текст. Ссылки — обычные `<a>`, внешние открываются в новой вкладке (`target="_blank" rel="noopener"`). Картинка `![…](…)` — ошибка Course: `<lesson>/lesson.md: строка N: картинки в Instructions не поддерживаются`. Подсветки кода в Instructions нет.
- Разметку и CSS можно брать из прототипа (ветка `prototype/lesson-screen`, вариант A), прототип не мержится.

### Runtime

Compiler отдаёт Workspace Lesson Tests под именем `./main` (договорённость 3). Остальное — как в PoC (договорённость 6). Тесты Runtime держат свои мини-Lesson прямо в тесте: PoC-задание Counter удаляется (тикет 03, Q12).

### Разработка инструмента и e2e (Q1)

- `npm run dev` поднимает Vite-сервер UI с HMR. `course.json` на нём отдаёт middleware, которая на каждый запрос вызывает модуль чтения Course для курса из переменной окружения (корневой скрипт задаёт `courses/react-hooks`). Ошибки Course → ответ 500 с теми же строками, UI показывает «Не удалось загрузить курс». Код инструмента путь `courses/` не содержит, его передаёт только скрипт корня.
- `npm run test:e2e` собирает UI, затем собирает курс React Hooks настоящим `codda build` и запускает Playwright. Основной проект e2e открывает эту сборку из подпути `/codda/`, как пилот на GitHub Pages. Проект `dev` оставляет один smoke-тест на `npm run dev`.
- e2e «Solution каждого Lesson проходит» перебирает Lesson из собранного `course.json`. Он закрывает удалённый `courses/courses.test.ts`, пока `author-cli` не введёт `codda test`.
- CI выкладывает на Pages ровно ту сборку `codda build`, которую проверил e2e.

### Граница ADR-0006 (Q3)

- В tsconfig пакета `codda` `include` и `rootDir` ограничены пакетом, поэтому импорт из `courses/` — ошибка `npm run typecheck`.
- Отдельный тест (Node) проходит по исходникам пакета, разрешает каждый статический и динамический импорт (включая `?raw` и `?url`) и падает, если файл лежит вне пакета и вне `node_modules`. Vite такой импорт не ловит, поэтому нужен и тест. Тест идёт в `check`.
- e2e и тесты в корне репозитория (не код инструмента) могут читать файлы курса как данные.

## Testing Decisions

Хороший тест проверяет внешнее поведение на самом высоком шве: что видит студент на странице, что печатает CLI и с каким кодом завершается, что лежит в выходной папке. Внутренние функции модуля чтения (схема, кросс-файловые правила) отдельно не тестируются, только через CLI. Ошибки и граничные случаи тестируются в тикете, где появляется поведение (правило MVP из `CLAUDE.md`).

Швы:

- **CLI как процесс:** `codda build` на временной папке Course, которую тест пишет сам (фикстуры — в тесте, не в `courses/`). Проверяются stdout/stderr, код выхода и содержимое `--out`. Раннер — тот же, что у теста CLI из `misc-03` (`npx codda --version`). Prior art: тест каркаса CLI из `misc-03`.
- **Компонент экрана Lesson в браузере (Vitest browser mode):** экран получает литерал `CourseData`. Проверяются тулбар, вкладки, Test Report, Reset и undo, «Решение». Prior art: `App.test.tsx` (настоящий Run в браузере, `page.getByRole`).
- **Runner:** Lesson Tests импортируют `./main`. Prior art: `runner.test.ts`.
- **e2e (Playwright) на сборке `codda build`:** загрузка `course.json`, фрагмент `#/…`, неизвестный id, ошибка загрузки (Playwright `route` отдаёт 404), Instructions с форматированием и экранированным HTML, все Solution React Hooks дают PASS. Всё офлайн через фикстуру `e2e/offline`. Prior art: `golden-path.e2e.ts`, `sandbox-isolation.e2e.ts` (переводятся на курс React Hooks).
- **Граница ADR-0006:** Node-тест по исходникам пакета; проверяется и на нарушителе (тест-фикстура с импортом из `../courses`), и на чистом коде.

## Out of Scope

- Дерево Course, `← Предыдущий` / `Следующий →`, кнопка «Следующий урок →» в баннере PASS, прогресс, Workspace в `localStorage` — `course-ux`.
- `■ Отмена`, вкладка «Console», сопоставление строк ошибок с файлом студента и подчёркивание строки ошибки компиляции в редакторе (Q4), async-ошибки — `runtime-hardening`.
- Вкладка «Проблемы», diagnostics, общий конфиг TS, loader по расширению Workspace (`.ts` vs `.tsx`) — `ts-tooling`.
- `package.json` / `package-lock.json` / `.npmrc` Course, Dependency Artifact в `deps/<hash>/`, проверка версий — `dependency-artifacts`.
- Полный `codda build` (поиск `course.yaml` вверх, устаревший `dist-tool/`, маркер `.codda-build`), команды `test`, `dev`, `init`, `lesson`, шаги `codda test`/`codda build` в CI по всем курсам — `author-cli`.
- Картинки и файлы рядом с `lesson.md`, подсветка кода в Instructions, MDX, проверка лишних файлов в папке Lesson, плашка «Starter обновлён».

## Further Notes

- Перевод React Hooks делается руками: пять Lesson не стоят скрипта. `title` без префикса «React Hooks N/5:», в тестах `./App` → `./main`. Названия элементов вроде `<p>` в Instructions стоит обернуть в обратные кавычки: иначе они покажутся как текст `<p>` (raw HTML), что верно, но выглядит хуже кода.
- Пока нет `dependency-artifacts`, все Course используют один PoC-артефакт (React 19.3.0). Курс React Hooks другого не требует.
- Сборка с несколькими курсами не поддерживается: одна сборка — один Course (тикет 05).
