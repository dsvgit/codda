## Раунд 1

### Q1 — Как разработчик инструмента запускает UI и на чём гоняются e2e

После фичи UI без `course.json` пуст, а импортировать курс он больше не может (ADR-0008). Сейчас `npm run dev` — голый Vite, e2e идут на Vite dev и на `vite preview` от `dist/` из подпути `/codda/`. `codda dev` появится только в `author-cli`, и в нём нет HMR UI: он раздаёт заранее собранный UI.

- **(a) Middleware в Vite + e2e на настоящем `codda build`.** `npm run dev` — Vite с HMR UI; `course.json` отдаёт middleware, которая на каждый запрос вызывает тот же модуль чтения Course, что и `codda build`. Курс задаёт переменная окружения, корневой скрипт подставляет `courses/react-hooks`, в коде инструмента пути к курсам нет. Правка Instructions видна после перезагрузки, правка UI — сразу. `npm run test:e2e` = сборка UI → `codda build courses/react-hooks` → Playwright по этой сборке из `/codda/`: ровно то, что выкладывается на Pages и что потом проверит `codda test`. На dev-сервере остаётся один smoke-тест, чтобы `npm run dev` не сгнил. Плюс e2e «Solution каждого Lesson даёт PASS» по собранному `course.json` — он заменяет удаляемый `courses/courses.test.ts` до `codda test`.
- **(b) `codda build` в служебную папку + Vite с ней как `publicDir`.** Без middleware, но `course.json` устаревает до перезапуска `npm run dev`. e2e — как в (a).
- **(c) Только `codda dev` из `author-cli`.** Без HMR UI, а до `author-cli` UI вообще не запустить. Тикет `lesson-manifest/01` без него не позеленеет.

➡️ **Рекомендация:** (a). Middleware — постоянный инструмент разработки, а не одноразовый скрипт: она вызывает тот же модуль, что и CLI. e2e идут на настоящей сборке, поэтому выкладка в CI берёт тот же `dist/`, что проверил e2e. Полный прогон e2e на двух серверах удвоил бы время без пользы.

### Q2 — Где Markdown превращается в HTML

Instructions — CommonMark + GFM, raw HTML как текст, картинки — ошибка Course (тикет 03 Плана). Для проверки картинок Markdown всё равно разбирается в Node.

- **(a) В `codda build`:** `course.json` несёт готовый HTML, UI его только вставляет. Разбор и проверка в одном месте, `marked` не попадает в бандл UI, `codda dev` и `codda test` получают то же самое.
- **(b) В браузере:** `course.json` несёт исходный Markdown, UI рендерит его `marked` с экранированием HTML. Формат `course.json` ближе к исходникам, но `marked` попадает в бандл UI, а разбор живёт в двух местах.

➡️ **Рекомендация:** (a). `course.json` пишет только наш `codda build`, поэтому вставлять из него HTML безопасно: raw HTML уже экранирован при сборке.

### Q3 — Чем проверять границу ADR-0006

Тикет 06 Плана оставил способ этой фиче, а `misc-03` — включение `rootDir`.

- **(a) `rootDir`/`include` пакета + Node-тест импортов.** `tsc` ловит обычные импорты из `courses/`. Тест разрешает все импорты исходников пакета, включая `?raw`/`?url` Vite, которые `tsc` пропускает через объявления `vite/client`.
- **(b) Только `rootDir`.** Проще, но `import x from "../../../courses/…/lesson.md?raw"` пройдёт и `tsc`, и Vite.
- **(c) Правило линтера** (`no-restricted-imports`). Линтера в репозитории нет, а новая зависимость вне списка `README.md` означает остановку.

➡️ **Рекомендация:** (a), отдельным маленьким тикетом `lesson-manifest/05`.

### Q4 — Подчёркивание строки ошибки компиляции в редакторе

Тикет 04 Плана: «Строка ошибки компиляции ещё и подчёркивается в редакторе». По таблице `README.md` «строки ошибок в файле студента» оставляет `runtime-hardening`. Сейчас esbuild отдаёт строку в том файле, где ошибка: это может быть Workspace или Lesson Tests, и UI их не различает.

- **(a) В `runtime-hardening`:** там Test Report узнаёт, в каком файле ошибка, и подчёркивание появляется вместе с этим знанием (через `@codemirror/lint`, который потом берёт и `ts-tooling`). В `lesson-manifest` — только текст `Строка N:M — сообщение` во вкладке «Тесты».
- **(b) В `lesson-manifest`:** подчёркивать сразу. Тогда ошибку в Lesson Tests подчеркнёт в коде студента, пока `runtime-hardening` не разведёт файлы.

➡️ **Рекомендация:** (a). Спека `runtime-hardening` должна взять этот пункт явно.

## Предложения в общие документы

**`CONTEXT.md`:**

- **Run:** «Одно нажатие „Run tests“» → «Одно нажатие „▶ Запустить тесты“»: кнопка в UI теперь русская (тикет 04 Плана).
- **Starter:** добавить, что студент видит его под именем `main.ts` или `main.tsx`; сейчас имя есть только в Lesson Manifest.
- Новый термин **Course Build** (_Avoid_: dist, бандл курса): выход `codda build`, статическая папка из готового UI, `course.json` и Dependency Artifact. Его выкладывают на хостинг и его же проверяют e2e и `codda test` (ADR-0008).

**ADR:** новых не нужно. Решение Q2 (HTML Instructions готовится в `codda build`) можно дописать строкой в Consequences ADR-0008.
