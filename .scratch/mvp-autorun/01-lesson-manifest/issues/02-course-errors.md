# 02: Все ошибки Course сразу, одной строкой на ошибку

**What to build:** Author запускает `codda build` на Course с ошибками и за один запуск видит **все** ошибки по всем файлам, по одной строке: `<файл от корня Course>: <путь к полю>: <сообщение>`, по-русски. Код выхода `1`, сборка не создаётся. Правила — все из `## Answer` тикета 03 Плана решений, кроме картинок в Instructions (тикет 04) и зависимостей (`dependency-artifacts`). Те же строки показывает ответ 500 dev-сервера инструмента.

Подробности — [spec.md](../spec.md), «Формат Course на диске» и «Модуль чтения Course».

**Blocked by:** 01a

**Status:** done

Все проверки — тестами CLI как процесса на временных Course, которые пишет сам тест. Каждый тест сверяет точную строку ошибки и код `1`.

- [x] `course.yaml`: нет `id`, `title`, `modules`; пустой `modules`; Module без `title` или с пустым `lessons`; путь поля как `modules[0].lessons[2]`
- [x] `id` Course и id Lesson в `lessons` не kebab-case (`React-Hooks`, `use_state`, `01-`) → ошибка
- [x] Неизвестное поле в `course.yaml` и во frontmatter (например, `dependencies`) → ошибка с именем поля
- [x] Синтаксическая ошибка YAML в `course.yaml` и во frontmatter → `<файл>: строка N: <сообщение>`
- [x] Lesson из `course.yaml` нет на диске; папка с `lesson.md` в корне Course не указана в `course.yaml`; id повторяется внутри Module и между Module
- [x] Нет `lesson.md`; нет frontmatter; нет `title` или он пустой
- [x] Нет `main.ts`/`main.tsx` или есть оба; нет `solution.*` с расширением `main`, в том числе `solution.ts` при `main.tsx`; нет `lesson.test.ts`/`.tsx` или есть оба
- [x] Папка вроде `node_modules/` или `dist/` без `lesson.md` ошибкой не считается
- [x] Несколько ошибок в разных файлах и разных Lesson выводятся все за один запуск, в стабильном порядке (`course.yaml`, затем Lesson в порядке `course.yaml`)
- [x] Все сообщения на русском, включая сообщения Zod
- [x] При ошибках папка `--out` не создаётся, а существующая не меняется
- [x] Курс React Hooks проходит без ошибок
- [x] `npm run typecheck`, `npm test`, `npm run test:e2e` зелёные

## Comments

- **2026-10-04 — реализация (агент).**
  - **Модуль чтения** `packages/codda/cli/read-course.ts` переписан под полный набор правил; `codda build` и dev-сервер не менялись, оба печатают его строки. Порядок вывода: синтаксис и схема `course.yaml` (в порядке Zod), затем кросс-файловые ошибки `course.yaml` в порядке списка, затем папки с `lesson.md`, не указанные в `course.yaml` (по алфавиту), затем ошибки Lesson в порядке `course.yaml`.
  - **Все ошибки за один запуск:** если схема `course.yaml` не прошла, Lesson всё равно проверяются по списку `modules[].lessons`, взятому из YAML как есть (только валидные kebab-case id). Не проверяются Lesson только при синтаксической ошибке YAML в `course.yaml`: списка нет. Если в `course.yaml` не указан ни один Lesson, проверка «папка не указана в `course.yaml`» не выполняется, иначе на `modules: []` каждая папка дала бы лишнюю строку.
  - **Сообщения по-русски.** Локаль Zod `ru` пишет типы по-английски («ожидалось string, получено undefined»), поэтому частые issue получили свои слова: нет поля или `null` → «обязательное поле», другой тип → «ожидается строка/список/объект», пустая строка → «не может быть пустым», пустой список → «список не может быть пустым», неизвестный ключ → по строке на ключ `<путь>.<ключ>: неизвестное поле`. Остальное — текст локали `ru`. Нужен `safeParse(…, { reportInput: true })`, иначе `input` в issue нет.
  - **Синтаксис YAML:** номер строки теперь через `LineCounter` пакета `yaml` (в 01a с `prettyErrors: false` `linePos` не заполнялся, и строка всегда была 1). Английские сообщения `yaml` заменены по коду: `DUPLICATE_KEY`, `BAD_INDENT`, `TAB_AS_INDENT`, `MISSING_CHAR`, остальные — «ошибка синтаксиса YAML»; одинаковые строки схлопываются. Пустой YAML (`course.yaml` или frontmatter `---\n---`) читается как `{}` — ошибки «обязательное поле», а не «ожидается объект».
  - **Формат строк про файлы Lesson** — `<id>/: нет lesson.md`, `<id>/: нет main.ts или main.tsx`, `<id>/: есть и main.ts, и main.tsx — нужен один`, `<id>/: нет solution.tsx — расширение как у main.tsx`, то же для `lesson.test.*`; Lesson из списка без папки — `course.yaml: modules[i].lessons[j]: нет папки урока <id>`; повтор — `… урок <id> уже указан в modules[i].lessons[j]`; неуказанная папка — `<id>/lesson.md: урок <id> не указан в course.yaml`. ENOENT со стеком из 01a больше не возникает.
  - **Тесты** — `cli/build.test.ts`, блок «Course errors»: CLI как процесс, точные строки, код `1`, `--out` не создан; отдельно «папки без `lesson.md` не Lesson» и «существующий `--out` не меняется». Тест 500 dev-сервера в `cli/dev-server.test.ts` теперь сверяет точный текст.
  - **TDD-оговорка:** red → green видел для обязательных полей, пустых значений и типов, неизвестных полей и синтаксиса YAML. Кросс-файловые правила, файлы Lesson и порядок вывода написаны одним заходом вместе с переписанным модулем, их тесты — сразу после кода; красными их подтвердил прогоном против модуля из 01a (9 из 9 падают). Тесты kebab-case, «`node_modules/` не Lesson» и «`--out` не меняется» зелёные и на 01a: поведение уже было.
  - **Находки вне критериев:** `codda build --out a --out b` по-прежнему молча берёт последнее значение (к `author-cli`). Лишние файлы в папке Lesson не проверяются (по спеке). Номер строки у ошибок схемы (не синтаксиса) не выводится — только путь к полю.
