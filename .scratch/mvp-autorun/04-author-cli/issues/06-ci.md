**What to build:** CI этого репозитория проверяет каждый курс в `courses/` так же, как будет проверять CI репозитория курса: `npx codda test`, затем `npx codda build`. На GitHub Pages выкладывается проверенный `dist/` пилотного курса, а не сборка инструмента. Адрес пилота `https://dsvgit.github.io/codda/` не меняется. ## Comments

- Если CI `check` после правки займёт заметно больше времени (Chromium, сборка артефакта), это записывается сюда с цифрами, а не оптимизируется в этом тикете. Двойного `npm ci` нет: Q12 раунда 2.
- **Шаг курсов в `ci.yml`** — один шаг `bash` после `npm run test:e2e`: `for course in courses/*/`, пропуск папок без `course.yaml`, в каждой `(cd "$course" && npm ci && npx codda test && npx codda build)` под `set -euo pipefail`, вывод курса — в `::group::`. `PILOT_COURSE: courses/react-hooks` — `env` уровня workflow, `upload-pages-artifact` берёт `${{ env.PILOT_COURSE }}/dist/`; условие выкладки и job `deploy` не тронуты. `dist/` пилота теперь пишет шаг курсов (`npx codda build` из папки курса), а не `codda build` внутри `test:e2e` — e2e проверяли ту же сборку, шаг курсов её пересобирает тем же `codda` из тех же файлов.
- **Время** — локально (macOS, кэш `.codda/` есть) шаг курса React Hooks: `npm ci` ~1 с, `codda test` ~7 с, `codda build` ~1 с. В CI кэша `.codda/` нет: `codda test` соберёт Dependency Artifact сам (~секунды), `codda build` попадёт в кэш. Цифры CI — после push.
- **`--ci`** — флаг только `init` (`COMMAND_OF`), проверяется первым в `init`: неизвестное значение — `codda: --ci: github или gitlab, а не <значение>`, код `2`, папка не создаётся. Шаблоны — `packages/codda/templates/ci/github.yml` и `gitlab.yml`, подстановка одна — `{{playwright}}` = `dependencies.playwright` пакета `codda`; файл пишется в `.github/workflows/codda.yml` или `.gitlab-ci.yml` и попадает в список созданных файлов. `copyTemplate` не переиспользован: он копирует папку целиком и подставляет `id`/`title`, а тут один файл в другой путь.
- **GitHub-шаблон** повторяет `ci.yml` этого репозитория: `options: --user 1001` у контейнера (как здесь — Chromium под root без `--no-sandbox` не стартует), `upload-pages-artifact@v5` шагом `check` с тем же условием, что у `deploy`; `concurrency` `pages` без отмены. Комментарий в начале — что настроить в репозитории (Pages: GitHub Actions, branch protection с `check`).
- **GitLab-шаблон**: `image: $CODDA_IMAGE` верхнего уровня (его берёт `check`), у `deploy` — `$CODDA_DEPLOY_IMAGE` (плейсхолдер, образ с AWS CLI). Выкладка: `aws s3 sync … --delete --exclude index.html --exclude course.json --cache-control "public, max-age=31536000, immutable"`, затем `aws s3 cp` `index.html` и `course.json` с `no-cache` — точки входа последними. `--endpoint-url "$AWS_ENDPOINT_URL"` явно (старые AWS CLI переменную не читают). `rules: if: $CI_COMMIT_BRANCH == "main"`, `needs: [check]`. Переменные и требование HTTPS/`application/wasm` — в комментарии в начале. `immutable` на всё, кроме точек входа, безопасно: `esbuild.wasm` и бандлы UI у Vite с hash в имени, `deps/<hash>/` — тоже.
- **Тесты**: `cli/ci-templates.test.ts` — `init --ci github|gitlab` процессом во временной папке, файл разбирается `yaml` `parse`: job'ы, команды `npm ci`/`npx codda` по порядку, версия Playwright в образе/комментарии, условие выкладки только на `main`; `--ci bogus` — код `2`, пусто; `init` без `--ci` — CI-файла нет. «Unit-тест шаблонов» и «тест CLI процессом» совмещены: подстановка живёт в `init`, отдельный модуль ради теста не заводился (правило 3). Шаблон не проверяется GitHub/GitLab-линтером — только структура YAML.
- **Тесты после кода (честно):** красными увидены `--ci github`, `--ci gitlab`, `--ci bogus` (до кода `--ci` был неизвестным флагом). «`init` без `--ci` — CI-файла нет» зелёный сразу: это прежнее поведение.
- **Документы**: шапка `ci.yml`, README (абзац про `npx codda` и шаблоны CI, абзац про пилот, строка про `ci-templates.test.ts`), строка 4 (`| 4 |`) таблицы `docs/HOW-TO-PROCEED.md`.
