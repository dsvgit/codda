# 06: CI — `codda test` + `codda build` по курсам, выкладка сборки курса, шаблоны `init --ci`

**What to build:** CI этого репозитория проверяет каждый курс в `courses/` так же, как будет проверять CI репозитория курса: `npx codda test`, затем `npx codda build`. На GitHub Pages выкладывается проверенный `dist/` пилотного курса, а не сборка инструмента. Адрес пилота `https://dsvgit.github.io/codda/` не меняется. Команда `codda init --ci github|gitlab` кладёт в новый Course готовый CI с проверкой и выкладкой по решению тикета 06 Плана решений. Спека — «Шаблоны CI», «CI этого репозитория».

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] Job `check` в `ci.yml` после проверок инструмента обходит каждую папку `courses/*` с `course.yaml`. Для каждой выполняются `npm ci`, `npx codda test` (`CI=true` уже выставлен в Actions) и `npx codda build`. Список курсов в workflow не захардкожен
- [ ] Путь пилотного курса задан одной переменной в начале workflow (`courses/react-hooks`). `upload-pages-artifact` берёт его `dist/` вместо сборки инструмента. Job `deploy` не меняется, условие «только push в `main`» сохраняется
- [ ] Шаблоны CI лежат в пакете `codda`. `codda init --ci github` кладёт `.github/workflows/codda.yml`, `--ci gitlab` — `.gitlab-ci.yml`. Другое значение — код `2`, без флага шаблона нет
- [ ] GitHub-шаблон: на PR и push в `main`; контейнер `mcr.microsoft.com/playwright:v<версия>-noble` с версией `playwright` пакета `codda`, подставленной при `init`; `npm ci` → `npx codda test` → `npx codda build` → `upload-pages-artifact`; job выкладки `deploy-pages` только на push в `main`, с `permissions`, environment `github-pages`, `concurrency`
- [ ] GitLab-шаблон:
  - `image: $CODDA_IMAGE` с комментарием «Node 24 и Chromium для Playwright <версия>»;
  - registry берётся из `.npmrc` курса;
  - job проверки: `npm ci`, `npx codda test`, `npx codda build`, `dist/` сохраняется как артефакт;
  - job выкладки только на `main`, образ — плейсхолдер. Она выполняет `aws s3 sync dist/ s3://$CODDA_S3_BUCKET/ --delete` с `AWS_ENDPOINT_URL`, ставит `Cache-Control: no-cache` на `index.html` и `course.json` и `immutable` на остальное. Требование HTTPS — в комментарии
- [ ] Unit-тест разбирает оба шаблона после подстановки пакетом `yaml` и проверяет ожидаемые job'ы, порядок команд `codda` и условие выкладки только на `main`
- [ ] Тест (CLI процессом): `init --ci github` и `init --ci gitlab` кладут файл с подставленной версией Playwright; `--ci bogus` даёт код `2`
- [ ] Документы: шапка `ci.yml`, README (раздел про `npx codda` и шаблоны CI). В строке 4 `docs/HOW-TO-PROCEED.md` отмечено, что выкладка берёт сборку курса
- [ ] Workflow проверен локально (`act` не нужен): команды шага курса, выполненные руками в `courses/react-hooks` при `CI=true`, дают код `0`. Зелёный `check` в контейнере Playwright подтверждает push оркестратора (ритуал autorun, шаг 6); если он красный, это стоп по правилам autorun
- [ ] `npm run typecheck`, `npm test`, `npm run test:e2e` зелёные

## Comments

- Если CI `check` после правки займёт заметно больше времени, из-за двойного `npm ci` (Further Notes спеки) или Chromium, это записывается сюда с цифрами, а не оптимизируется в этом тикете.
