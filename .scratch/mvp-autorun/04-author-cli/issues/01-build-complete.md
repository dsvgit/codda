# 01: `codda build` целиком — свежий UI, `--out`, маркер, «всё или ничего»

**What to build:** Author запускает `npx codda build` из любой папки курса и получает проверенную статическую сборку в `<курс>/dist` или в `--out`. Если готового UI (`dist-tool/`) нет или он устарел, CLI собирает его сам и сообщает об этом. При ошибке манифеста или зависимостей CLI ничего не пишет. Чужую непустую папку без маркера `.codda-build` он не трогает. В конце печатается список записанных файлов. Курс этого репозитория подключает `codda` через `file:` в `devDependencies`, и с этого тикета команды курса вызываются как `npx codda`. Тикет также вводит основу для тестов следующих тикетов: node-проект vitest и фикстуру «маленький `.ts`-курс во временной папке». Спека — раздел «Implementation Decisions»: «Поиск курса», «Готовый UI», «Сборка курса» (шаг npm и кэш артефакта уже сделаны в `dependency-artifacts`).

## Comments

- **Сделано.** `codda build [путь] [--out <папка>]`: поиск курса вверх от пути или текущей папки (`cli/find-course.ts`, отдаёт и id Lesson — понадобится `codda test <папка Lesson>`); проверка `--out` до сборки; свежесть `dist-tool/` по hash исходников (`cli/ui-build.ts`); сборка во временную `.codda/build-*`, затем замена целевой папки; маркер `.codda-build`; список файлов и строка `Курс собран в <out>, файлов: N`. Ошибка «нет собранного UI» из `lesson-manifest` убрана.
- **Hash UI** — sha256 по `src/`, `public/` (если есть), `index.html`, `vite.config.ts` и корневому `package-lock.json`; лежит в `dist-tool/.codda-ui-hash`. Пишет его плагин `codda-ui-hash` в `vite.config.ts` при любой `vite build`, поэтому `npm run build` (в `test:e2e`) тоже даёт свежий UI и `codda build` его не пересобирает. CLI сам собирает UI через `npx vite build --outDir <dist-tool> --emptyOutDir` (без `tsc`), вывод Vite показывает только при ошибке. В сборку курса файл hash не копируется.
- **Грубо:** hash включает и тесты `src/**/*.test.tsx` — правка теста пересобирает UI; для пилота не важно.
- **`--out`:** непустая папка без маркера (или файл) — код `2` до сборки, `.codda/` не создаётся. Перенос — `renameSync`; если `--out` на другом диске (`EXDEV`) — копирование. Ветка `EXDEV` тестом не покрыта.
- **Локально:** старый `courses/react-hooks/dist/` (собран до маркера) теперь отвергается с кодом `2` — его один раз удалить руками. В CI папки нет.
- **Курс React Hooks:** `"codda": "file:../../packages/codda"` в `devDependencies`, lockfile обновлён `npm install --offline`. `npm ci` курса ставит только symlink на пакет (зависимости `codda` берутся из корневого `node_modules`), hash артефакта сменился из-за lockfile, `importmap.json` `codda` не содержит (тест). `npx codda build` из `courses/react-hooks` и из `use-state/` проверен руками; тест запускает CLI как `node cli/codda.ts` в этих папках — в CI на шаге `npm test` у курса может ещё не быть `node_modules/.bin/codda`.
- **Тестовая основа:** node-проект `cli` в vitest уже был (misc/03); добавлен `cli/test-helpers.ts`: `tsCourse()` (курс `sum` + `greet` на `.ts` с настоящими `@codda/test`-тестами, Starter проваливает), `fakeUi()` (заглушка UI со свежим hash), `writeFiles()`, `runCodda(cwd, args, env)` — CLI процессом через `node`, без `npx` (во временной папке `npx` полез бы в registry). `deps.test.ts` переведён на `fakeUi`.
- **Тесты после кода / сразу зелёные:** «невалидный `lesson.md`» и «ошибка Dependency Artifact — старый `dist/` не тронут» прошли до правок — это поведение было и раньше (минимальный `build` падал до записи); оставлены как регрессионные. `uiSourceHash` написан вместе с `test-helpers.ts` до запуска красных тестов (помощнику он нужен для импорта). Остальные новые тесты увидены красными.
- Три теста пересборки UI делают настоящую `vite build` (по ~5–10 с), таймаут блока 180 с.
