# 01: `codda build` целиком — свежий UI, `--out`, маркер, «всё или ничего»

**What to build:** Author запускает `npx codda build` из любой папки курса и получает проверенную статическую сборку в `<курс>/dist` или в `--out`. Если готового UI (`dist-tool/`) нет или он устарел, CLI собирает его сам и сообщает об этом. При ошибке манифеста или зависимостей CLI ничего не пишет. Чужую непустую папку без маркера `.codda-build` он не трогает. В конце печатается список записанных файлов. Курс этого репозитория подключает `codda` через `file:` в `devDependencies`, и с этого тикета команды курса вызываются как `npx codda`. Тикет также вводит основу для тестов следующих тикетов: node-проект vitest и фикстуру «маленький `.ts`-курс во временной папке». Спека — раздел «Implementation Decisions»: «Поиск курса», «Готовый UI», «Сборка курса» (шаг npm и кэш артефакта уже сделаны в `dependency-artifacts`).

**Blocked by:** misc/03, фича `lesson-manifest` (минимальный `codda build`), фича `dependency-artifacts` (сборка Dependency Artifact внутри `build`)

**Status:** ready-for-agent

- [ ] Поиск курса: без пути `course.yaml` ищется вверх от текущей папки. Путь к папке Lesson даёт корень Course и id Lesson. Если курса нет, печатается «здесь нет курса: <путь>» и код `2`
- [ ] `dist-tool/`: hash исходников UI записывается в него при сборке UI. Если папки нет или hash другой, CLI печатает «Собираю UI codda…» и собирает UI. Это заменяет ошибку «нет собранного UI» из `lesson-manifest`. Если сборка UI упала, код `2`
- [ ] Сборка пишется во временную папку внутри `.codda/` и в конце заменяет целевую; в результате есть маркер `.codda-build`. При ошибке манифеста или Dependency Artifact целевая папка не меняется, ни один файл не записан, код `1`
- [ ] `--out <папка>`: несуществующая или пустая папка подходит, папка с `.codda-build` очищается. Если папка непуста и маркера нет, выводится ошибка до сборки, код `2`, папка не тронута
- [ ] Вывод: записанные файлы по одному на строку (путь от папки сборки) и итоговая строка
- [ ] `courses/react-hooks/package.json`: `"codda": "file:../../packages/codda"` в `devDependencies`, Dependency Artifact это поле игнорирует. `npx codda build` из `courses/react-hooks` и из папки его Lesson даёт одну и ту же сборку
- [ ] В vitest есть node-проект для тестов CLI рядом с браузерным, оба идут в `npm test`. Есть общий помощник: «скопировать фикстуру `.ts`-курса во временную папку и запустить в ней CLI процессом»
