- **Сценарии `e2e/pilot.e2e.ts`:** (1) с `./` все 5 Lesson подряд: решение из собранного `course.json` → «▶ Запустить тесты» → PASS → ✓ и «Пройдено N из 5» → «Следующий урок →»; на последнем — «Это последний урок курса», кнопки «Следующий урок →» нет, «Следующий →» неактивна, ✓ у всех 5 (граничный случай конца курса — в этом же сценарии, им курс и заканчивается); (2) Run на Starter каждого из 5 Lesson — FAIL, без «Следующий урок →», ✓ нет, «Пройдено 0 из 5»; (3) PASS первого Lesson, «Следующий урок →», во второй введено решение с припиской `// не доделано`, перезагрузка — открыт тот же Lesson (`#/use-effect`), Workspace с припиской, «Пройдено 1 из 5», ✓ у первого.
- **Красные прогоны:** (1) вместо Solution вводится Starter — падает на ожидании PASS у `use-state`; отдельно для конца курса — ожидание `toHaveCount(1)` у «Следующий урок →» на последнем Lesson — падает (кнопки нет); (2) ожидание PASS вместо FAIL на Starter — падает; (3) ожидание «Пройдено 2 из 5» после перезагрузки — падает. Затем зелёные, `--repeat-each 3` — 9 из 9.
- **Ввод в редактор — вставкой, а не `fill`.** Из-за отложенного флейка `fill` (текст задваивается под нагрузкой, `course.e2e.ts`) решение вставляется событием `paste` с `DataTransfer` после Ctrl/Cmd+A: CodeMirror применяет вставку одной транзакцией, как у студента, вставившего код. После вставки тест сверяет текст редактора с введённым, так что задвоение видно сразу, а не через ошибку компиляции. Существующие тесты на `fill` не переделывались (вне тикета).
