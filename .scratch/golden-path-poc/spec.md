# Spec: Golden Path PoC

**Status:** done — решение GO, см. [PoC Report](../../docs/poc-report.md)
**Срок:** 2–3 дня с AI. Это **не MVP** — это эксперимент, проверяющий техническую гипотезу.

## Problem Statement

Мы хотим строить платформу курсов, где код студента компилируется и проверяется тестами прямо в браузере, на собственном Runtime и без единого обращения к внешним сервисам (ADR-0001, ADR-0002). Мы не знаем, работает ли такой стек (CodeMirror 6 + esbuild-wasm в Worker + sandboxed iframe + собственный Test Harness) достаточно надёжно. Если строить всю платформу и узнать о фундаментальной проблеме через 6 недель — это дорого.

## Solution

Одна страница, один захардкоженный Lesson, **один редактируемый файл**. Студент читает Instructions, правит код в CodeMirror, жмёт **Run tests** и видит Test Report: какие тесты прошли, какие нет, с ошибками. Всё работает на localhost при выключенном Internet.

Строим в три микро-шага, каждый — отдельная гипотеза, чтобы при поломке сразу было понятно, где проблема:

1. **Step 0 — чистый TypeScript.** `export function add(a: number, b: number)`, тесты `add(2,3) === 5`. Доказывает цепочку: редактор → Worker → esbuild-wasm → Sandbox → Test Harness → UI.
2. **Step 1 — React + TSX + DOM.** Компонент `Counter` (показывает 0, `+` увеличивает, `−` уменьшает), тесты с рендером и кликами.
3. **Step 2 — Dependency Artifact.** `import { useState } from "react"` работает за счёт заранее собранного локального артефакта, без обращения к npm/CDN.

```
┌─────────────────────────────────────────────────┐
│ React: Counter                                  │
├───────────────────────┬─────────────────────────┤
│ Instructions          │ App.tsx (CodeMirror)    │
├───────────────────────┴─────────────────────────┤
│                 [ Run tests ]                   │
├─────────────────────────────────────────────────┤
│ ✓ renders initial value                         │
│ ✗ increments — expected "1", got "0"            │
│ ✓ decrements                        2 / 3 passed│
└─────────────────────────────────────────────────┘
```

## User Stories

1. Как студент, я хочу видеть Instructions рядом с редактором, чтобы понимать задачу, не переключаясь.
2. Как студент, я хочу видеть Starter-код в редакторе с подсветкой TS/TSX, чтобы начать с готовой заготовки.
3. Как студент, я хочу редактировать код в CodeMirror, чтобы решать задание прямо в браузере.
4. Как студент, я хочу нажать Run tests и получить результат за ~1–2 секунды, чтобы быстро итерировать.
5. Как студент, я хочу видеть каждый тест отдельно со статусом ✓/✗, чтобы понимать, что именно не так.
6. Как студент, я хочу видеть сообщение assertion-ошибки (expected/actual), чтобы понять, как исправить код.
7. Как студент, я хочу видеть итог «N / M passed», чтобы знать, решено ли задание.
8. Как студент, я хочу видеть понятную ошибку компиляции с номером строки, если я написал невалидный TS, вместо молчаливого падения.
9. Как студент, я хочу видеть runtime-ошибку (исключение в моём коде), чтобы отличать её от проваленного теста.
10. Как студент, я хочу, чтобы бесконечный цикл в моём коде завершался по timeout с понятным сообщением, а страница оставалась живой.
11. Как студент, я хочу после timeout снова нажать Run tests и получить нормальный результат, без перезагрузки страницы.
12. Как студент, я хочу, чтобы повторный Run всегда выполнялся «с чистого листа», без состояния от предыдущего запуска.
13. Как студент, я хочу писать React-компонент с `useState` и JSX, чтобы решать реальные frontend-задания.
14. Как студент, я хочу, чтобы тесты проверяли поведение моего компонента в DOM (рендер, клики), а не его исходный текст.
15. Как владелец платформы, я хочу, чтобы при работе страницы не было ни одного запроса за пределы localhost, чтобы доказать ADR-0002.
16. Как владелец платформы, я хочу, чтобы код студента не имел доступа к parent window, cookies и storage приложения (ADR-0003).
17. Как владелец платформы, я хочу, чтобы parent игнорировал сообщения неожиданной формы от Sandbox.
18. Как разработчик, я хочу автоматический e2e-тест Golden Path (FAIL → правка → PASS) с заблокированной внешней сетью, чтобы гипотеза проверялась одной командой.
19. Как разработчик, я хочу подменять Starter/Lesson Tests в коде одной константой, чтобы быстро проверять разные сценарии.
20. Как участник команды, я хочу получить короткий PoC Report с ответами на пять вопросов, замерами и найденными рисками, чтобы принять решение go/no-go.

## Implementation Decisions

- **Стек приложения:** Vite + React + TypeScript, Chrome, localhost. Без backend, БД, авторизации.
- **Lesson захардкожен** в одном модуле: `instructions`, `starter`, `tests` — строковые константы. Lesson Manifest, MDX, файловая структура урока — **не делаем**.
- **Один файл — одна строка.** Workspace в PoC — это одна строка `source`; никакого virtual FS.
- **Модули Runtime и их интерфейсы** (глубокие модули, маленькие интерфейсы):
  - **Compiler** — живёт в Web Worker. Интерфейс: `compile({ source, tests }) → { ok: true, code } | { ok: false, errors: CompileError[] }`. Внутри: esbuild-wasm `build` с виртуальным плагином-резолвером (`entry` импортирует тесты, тесты импортируют `./App`, `react` резолвится в Dependency Artifact). Выход — один ESM/IIFE-бандл. `esbuild.initialize({ wasmURL })` указывает на локально отдаваемый `.wasm`.
  - **Sandbox** — iframe `sandbox="allow-scripts"`, **без** `allow-same-origin`, пересоздаётся на каждый Run. Код доставляется через `srcdoc`.
  - **Test Harness** — минимальный собственный `test(name, fn)` / `expect(x).toBe(y)` / `toEqual` / `toContain` (~50–100 строк), поддержка async-тестов, вшивается в бандл. Для React — `react-dom/client` + `act` из `react` и обычные DOM-запросы. Testing Library и Vitest — не тащим в PoC.
  - **Runner** — оркестратор в parent: `run({ source, tests }) → Promise<TestReport>`. Компилирует через Worker, создаёт Sandbox, ждёт сообщение, применяет timeout (по умолчанию 5 с) — по timeout уничтожает iframe (и Worker, если завис компилятор).
- **Протокол postMessage** (Sandbox → parent): одно финальное сообщение `{ type: "codda:report", runId, report }`. Parent проверяет `event.source === iframe.contentWindow`, `type` и `runId`; всё остальное игнорирует.
- **Форма Test Report:**
  ```ts
  type TestReport =
    | { kind: "tests"; results: { name: string; status: "pass" | "fail"; error?: string }[] }
    | { kind: "compile-error"; errors: { message: string; line?: number; column?: number }[] }
    | { kind: "runtime-error"; message: string; stack?: string }
    | { kind: "timeout"; ms: number };
  ```
- **Dependency Artifact для `react`/`react-dom`:** локальный node-скрипт (esbuild native) один раз собирает React в ESM-текст и кладёт в `public/deps/`. Приложение загружает его с того же origin и отдаёт Compiler'у, который вшивает его в бандл (это обходит CORS для opaque-origin Sandbox — см. ADR-0003). Полноценный CI-пайплайн — вне скоупа (ADR-0005).
- **Редактор:** CodeMirror 6 с `@codemirror/lang-javascript` (TSX). Никакого autocomplete, diagnostics, Vim, табов.

## Testing Decisions

- **Хороший тест** проверяет внешнее поведение через публичный интерфейс модуля: «отдал source+tests → получил такой TestReport», а не внутренние вызовы esbuild или структуру DOM приложения.
- **Главный шов — `Runner.run({ source, tests }) → TestReport`.** Почти всё покрывается здесь: корректное решение → все pass; неверное → fail с сообщением; синтаксическая ошибка → compile-error; `throw` → runtime-error; `while(true){}` → timeout, а следующий Run снова работает. Эти тесты запускаются в реальном браузере (Playwright или Vitest browser mode), т.к. нужны Worker, wasm и iframe.
- **Второй шов — e2e Golden Path через UI** (Playwright): открыть страницу → Run → видим FAIL → вставить Solution в редактор → Run → «3 / 3 passed». Тот же тест повторяется с `page.route` / контекстом, блокирующим всё, кроме localhost, и падает на любой внешний запрос.
- **Test Harness** покрыть юнит-тестами нельзя осмысленнее, чем через Runner, — отдельный шов не вводим.
- Prior art в репозитории отсутствует — это первые тесты; их стиль станет эталоном.

## Out of Scope

Multi-file и virtual FS; Lesson Manifest, MDX, несколько Lesson, навигация; Reset/Solution reveal/progress/save-restore; npm install и CI-пайплайн зависимостей; TypeScript language service (autocomplete, diagnostics, `.d.ts`); preview/HMR/console; Vim; несколько framework'ов; Server Grader и Hidden Tests; авторизация, БД, backend; CSP, отдельный origin для Sandbox и прочий security hardening; браузеры кроме Chrome; авторский UI/CLI.

## Further Notes

- **Жёсткое правило:** не добавлять ни одной функции, которая не нужна для прохождения одного задания от начала до конца.
- **Критерий успеха:** страницу можно показать коллеге — «вот студент, вот App.tsx, он меняет код, жмёт Run, код реально компилируется и исполняется в браузере, тесты реально запускаются, неправильное решение → FAIL, правильное → PASS, Internet выключен».
- Если любой из пяти вопросов оказывается «нет/очень сложно» — останавливаемся и пересматриваем архитектуру до начала MVP.
- Известные риски, которые стоит замерить: размер и время инициализации `esbuild.wasm` (~10 МБ), время cold/warm Run, поведение `act` из React 19 вне jsdom.

## Итог

**2026-10-03.** Тикеты 01–05 — `done`, демо проведено. На все пять вопросов ответ «да», решение **GO**: [PoC Report](../../docs/poc-report.md).

Отклонения реализации от спеки (подробности — в `## Comments` тикетов):

- **Тесты Runner** — Vitest browser mode в полном Chromium (`channel: "chromium"`), e2e — Playwright. В `chrome-headless-shell` Sandbox делит процесс со страницей и timeout не срабатывает (тикет 02).
- **Dependency Artifact** скачивает сам Worker Compiler'а со своего origin, а не приложение. Ограничения ADR-0002/0003 те же, артефакты не гоняются через `postMessage` на каждый Run (тикет 03).
- **Бандл** — IIFE, импорты статические: ошибка импорта — это `compile-error`, а не `runtime-error` (тикет 02).
- **Deadline 5 с** — один на весь Run, включая холодный init `esbuild.wasm`. На медленной сети это даёт ложный timeout (R1 отчёта).
- **e2e** — все с блокировкой внешней сети, отдельного прогона Golden Path без блокировки нет (тикет 04).
- **Сверх спеки** после PoC: курс React Hooks в `courses/` (5 Lesson, открываются через `?lesson=<id>`) — для ручного прогона Runtime на разных хуках, без тикета. Формат Lesson там временный, до Lesson Manifest (roadmap, блок C).
