# 04: Доказательство offline и изоляции + e2e Golden Path

**What to build:** одна команда (`npm run test:e2e`) доказывает гипотезу целиком: Playwright открывает страницу, жмёт Run → видит FAIL, вставляет Solution в редактор → Run → «3 / 3 passed». Всё это — в контексте, где любой запрос не на localhost блокируется и валит тест. Плюс проверки изоляции Sandbox из ADR-0003.

**Blocked by:** 02, 03

**Status:** done

- [x] e2e Golden Path: FAIL → правка → PASS
- [x] Тот же сценарий с блокировкой внешней сети; список всех сетевых запросов страницы логируется, внешних — ноль
- [x] Тест: код студента, пытающийся прочитать `parent.document`, `document.cookie`, `localStorage`, получает ошибку/пустоту, а не данные приложения
- [x] Тест: Sandbox, присылающий сообщения чужой формы или с чужим `runId`, не меняет UI
- [x] Поддельный `fetch("https://example.com")` из кода студента не проходит (фиксируем фактическое поведение — блокировка тестом/CSP-заголовком dev-сервера)

## Comments

**2026-10-03 — реализация (агент).** `npm run test:e2e` — Playwright (`@playwright/test` 1.63, полный Chromium, `channel: "chromium"`) поднимает dev-сервер Vite на `localhost:5179` и гоняет 4 теста из `e2e/`. Все они работают в фикстуре `e2e/offline.ts`: `context.route` обрывает любой запрос не на localhost, `context.on("request")` логирует в stdout все запросы страницы, а после теста фикстура падает, если список оборванных запросов не совпал с `expectedExternal` (по умолчанию пустой).

- **Golden Path offline:** Run → `0 / 3 passed` → Solution в редактор → Run → `3 / 3 passed`. Страница делает 30 запросов, все на localhost: страница и модули Vite, Worker Compiler'а, `esbuild.wasm`, `deps/manifest.json` и три Dependency Artifact. Запросы Worker'а Playwright видит. Sandbox (`srcdoc`) своих запросов не делает. Внешних запросов — 0.
- **Изоляция:** до Run parent ставит себе `document.cookie` и `localStorage`. Код студента на верхнем уровне читает `parent.document.cookie`, `document.cookie` и `localStorage.getItem` и бросает исключение с результатом. Фактически все три чтения бросают `SecurityError`, данные приложения в Test Report не попадают.
- **Сообщения чужой формы:** код студента до настоящего отчёта шлёт в parent строку, отчёт с чужим `runId`, чужой `type`, отчёт со своим `runId`, но с битой формой `results`, и отчёт `kind: "timeout"` (его Sandbox слать не может). Parent всё это игнорирует, UI показывает настоящий результат `0 / 3 passed`.
- **`fetch("https://example.com/")` из кода студента** обрывается **только блокировкой теста** (`net::ERR_BLOCKED_BY_CLIENT`), Run при этом проходит нормально. CSP-заголовок в dev-сервер не добавляли: CSP в спеке вне скоупа PoC.
- Фикстура считает внешние запросы по полному логу (`context.on("request")` + WebSocket'ы страницы), а не по тому, что поймал `route`. Поэтому запрос, прошедший мимо роутинга, тоже валит тест.
- Спека говорит «тот же тест повторяется» с блокировкой. Отдельного прогона Golden Path без блокировки нет: блокировка включена для всех e2e (`auto`-фикстура), это строже.
- Стабильность: 20 / 20 при `--repeat-each 5` с 1 и с 2 workers.
- **Тесты не пустые — проверено мутациями** (каждая валит свой тест): `allow-scripts allow-same-origin` в Runner → тест изоляции красный. Без проверки `runId` → UI показывает `✓ forged 1 / 1 passed`. `fetch("https://cdn.example.com/…")` в `main.tsx` → Golden Path красный: фикстура видит внешний запрос.

**Риски для отчёта (05):**
- **Без блокировки в браузере код студента ходит в сеть.** Проверено отдельным скриптом с локальным HTTP-сервером: `fetch` из `sandbox="allow-scripts"` доходит до сервера с `Origin: null`. Ответ не читается только из-за CORS (`TypeError: Failed to fetch`), а `mode: "no-cors"` проходит. Значит, opaque origin не мешает утечке данных через URL/тело запроса. Закрывать на MVP: CSP `connect-src` для Sandbox (в `srcdoc` наследуется от parent) и/или отдельный origin Sandbox (roadmap, блок Security).
- **Код студента знает `__coddaRunId` и может прислать поддельный «3 / 3 passed» правильной формы.** Parent его примет: `runId` защищает от чужих/старых Run, а не от самого Sandbox. Для PoC это допустимо (ADR-0004, проверка только в браузере), но такой результат нельзя засчитывать как прохождение — это работа Server Grader.
- **Холодный Run под нагрузкой не укладывается в 5 с.** При 6 параллельных браузерах (`--repeat-each 5`, 12 ядер) часть первых Run заканчивается «Timed out»: Run-у не хватает 5 с из-за компиляции `esbuild.wasm` и холодного dev-сервера. Поэтому в `playwright.config.ts` стоит `workers: 2`. На MVP: не включать холодный init в deadline Run (подтверждает риск из 02).
- «Offline» доказан блокировкой внешних запросов в Playwright, а не физически выключенной сетью. Ручной прогон с выключенным Wi-Fi — часть демо в 05.

Не протестировано (на отдельный проход):
- e2e в production-сборке (`vite preview`) — сейчас только dev-сервер.
- Попытки Sandbox навигировать parent (`top.location`), открыть окна, `alert` — sandbox без `allow-top-navigation`/`allow-popups`/`allow-modals` их запрещает, тестами не закреплено.
- Сообщения в parent от других окон/фреймов (не Sandbox) — проверка `event.source` тестом не покрыта: все поддельные сообщения шлёт сам Sandbox.
- Гонка в тесте `fetch`: если Runner удалит iframe раньше, чем `route` оборвёт запрос, ошибка будет `ERR_ABORTED`, а не `ERR_BLOCKED_BY_CLIENT`. Не воспроизводилась (30+ прогонов). `await` на верхнем уровне модуля студента недоступен: бандл в формате IIFE.
